# Lumée — 跨境独立站 SaaS

规划文档见 [docs/PLAN.md](docs/PLAN.md)。

## 目录

| 目录 | 说明 |
|---|---|
| `backend/` | Laravel 12（PHP 8.2）：商家后台 API + 店铺前台（服务端渲染主题）+ 平台首页 |
| `admin/` | 商家后台：Vue 3 + Vite + TypeScript + Naive UI（品牌主题） |
| `packages/ui-tokens/` | 品牌设计 Token（色板、字体），后台和主题共用 |
| `brand/` | Logo 原图、蝴蝶图标、favicon |
| `tools/composer.phar` | Composer（本机未全局安装） |
| `deploy/Caddyfile` | 生产环境 Caddy 配置示例（自动 HTTPS，见 [docs/https.md](docs/https.md)） |

## 本地启动

1. **数据库**：在 phpStudy 中启动 MySQL。本项目使用数据库 `lumee_saas`（字符集 utf8mb4，已经建好）。
   > 注意：MySQL 里另有一个名为 `lumee` 的库，属于另一个项目（Bagisto），本项目不会使用它。
2. **后端**
   ```bash
   cd backend
   php artisan migrate
   php artisan db:seed --class=DemoSeeder   # 可选：生成演示店铺和 4 件珠宝商品
   php artisan serve --port=8000
   ```
   演示账号写在 `database/seeders/DemoSeeder.php` 的注释里。
3. **商家后台**
   ```bash
   cd admin
   npm run dev
   ```
   打开 http://localhost:5280 注册开店。

| 地址 | 内容 |
|---|---|
| http://localhost:8000 | 平台首页 |
| http://localhost:5280 | 商家后台（`/api` 请求会代理到 8000 端口） |
| http://{店铺handle}.lumee.localhost:8000 | 店铺前台（浏览器会自动把 `*.localhost` 解析到本机） |

4. **队列和定时任务**（邮件、商品导入、每日汇率需要）
   ```bash
   cd backend
   php artisan queue:work      # 一个终端
   php artisan schedule:work   # 另一个终端：每日汇率、清理未用图片、自动化邮件（每 10 分钟）、弃单提醒邮件（每 15 分钟）、定时群发邮件（每分钟）、邀请评价邮件和物流跟踪（每小时）
   ```
5. **HTTPS 证书（本机 phpStudy 需要设置一次）**：服务器要访问外部 HTTPS 地址（汇率接口、导入时下载商品图片、Stripe）。phpStudy 自带的 PHP 默认没有 CA 证书，会报 `cURL error 60`。解决方法：
   1. 下载 https://curl.se/ca/cacert.pem；
   2. 在 php.ini 中设置 `curl.cainfo` 和 `openssl.cafile`，都指向这个文件；
   3. 重启 PHP。

## 获客雷达（找潜在 B2B 客户）

后台左侧菜单「获客雷达」，代码在 `backend/app/LeadFinder/`。流程：搜索地图商家 → 读取对方官网公开的邮箱 / 电话 / WhatsApp / 社交账号 → 按匹配度打分（0–100，A/B/C/D）→ 生成开发信 → 跟进，或转为 B2B 公司。

- **数据来源**：Google 地图 Places API (New)（推荐，需要 API Key，按调用次数收费）；OpenStreetMap（免费，数据较少；Overpass 服务连不上时会自动改用 Nominatim）。
- **官网和社媒渠道**（「在哪里找」可以多选，代码在 `Sources/WebSearchSource.php`）：通过 SerpApi 的 Google 搜索结果，找公司官网，以及公开的 Facebook 主页、Instagram 账号、LinkedIn 公司页和 TikTok 账号。
  - 读取搜索结果里的标题、链接和摘要：商家常把邮箱、电话、WhatsApp、官网和粉丝数写在简介里，这些会自动识别。帖子、视频、群组、个人 LinkedIn、电商平台和黄页网站会被跳过。
  - **不会登录或抓取社媒网站本身**。从简介里找到官网后，再像其他线索一样读取官网。
  - 和「选品雷达」共用同一个 SerpApi Key。每次搜索最多 40 次 Google 查询（渠道 × 城市 × 关键词）。
  - 同时选了地图和官网 / 社媒时，会分成两个搜索任务，各自显示进度。
  - AI 一句话拓客会同时建议在哪些渠道找（例如小品牌、网店选 Instagram / TikTok，大型进口商选 LinkedIn）。
- **Instagram 资料（可选）**：填写 Meta 访问令牌和你自己的 Instagram 商业账号 ID 后，用官方的 Business Discovery 接口读取在 Instagram 上找到的商家的简介、官网链接和粉丝数（只适用于商业账号和创作者账号；个人账号会注明“读不到资料”）。
- **Hunter.io（可选）**：官网没有公开公司邮箱时，按域名查找网上公开过的工作邮箱，只保留可信度 70 分以上的。有姓名和职位的人（如采购经理）显示在线索详情的「联系方式」里。
- **粉丝数**：没有地图评价的线索，按社媒粉丝数计算规模分（1 千以上 / 1 万以上），导出的表格也包含粉丝数和 TikTok。
- **AI**：填写 Claude API Key 后，会读对方官网判断客户类型和匹配度，并用当地语言写开发信（附中文翻译）。不填时用规则打分和英文模板。
- **Key 的配置**：每个店铺在「获客雷达 › 设置」里填写（加密保存）；也可以在 `.env` 里配置平台统一的 `GOOGLE_PLACES_KEY`、`ANTHROPIC_API_KEY`，店铺没填时使用。
- 搜索在**队列**里运行，需要 `php artisan queue:work`。
- **AI 一句话拓客**：输入“帮我找墨西哥做手机配件批发的公司”，AI 自动填好产品、国家、城市和当地语言关键词。
- **邮箱验证**：每个邮箱都会检查域名有没有收信服务器（MX 记录），并区分公司邮箱、个人邮箱和免费邮箱。官网没公开邮箱、但域名能收信时，给出推测的 info@ 邮箱，并标明“推测”。
- **跟进提醒**：每条线索可以设置下次跟进的日期，首页显示“今日待跟进”。
- **地图视图**：线索按评分显示在地图上，默认使用 OpenStreetMap 官方底图（只适合少量使用）；访问量大时，用 `VITE_MAP_TILES` 换成付费的地图底图服务。
- 运营商门店和大型连锁（T-Mobile、Verizon、Best Buy 等）会自动过滤掉，因为它们统一由总部采购。开启了防爬虫保护的网站不会去绕过，只记录为“未能读取”。

## 开发信序列（自动发开发信和跟进）

「营销 › 开发信」，代码在 `backend/app/Outreach/`。

- **用自己的邮箱发**：在「发信邮箱」里填 SMTP（发信）和 IMAP（收信，用来识别回复和退信）。邮件从商家自己的地址发出，回复也回到自己的邮箱；密码加密保存。Gmail / Outlook 要用“应用专用密码”。IMAP 用纯 PHP 库 `webklex/php-imap`，服务器不需要 IMAP 扩展。
- **序列**：第一封 + 最多 4 封跟进，每封设置“上一封之后几天”。跟进邮件标题留空时，作为回复发在同一个邮件线程里（`Re: …`，带 In-Reply-To / References）。
  - 可用变量：`{{first_name}}`（对方名字，没有就用公司名）、`{{company}}`、`{{sender_name}}`、`{{sender_company}}`、`{{website}}`。
  - **AI 写第一封**（B 端客户）：用获客雷达的开发信 AI，按对方官网、用对方的语言写；同时把跟进模板翻译成同一种语言（保留变量）。写好后保存，预览和实际发出的内容一致。达人序列的第一封用「达人合作」的合作邀请（含推广码和佣金）。
- **谁会被加入**：在获客雷达勾选线索、或在达人合作里点「加入开发信序列」；也可以设置序列「自动加入」：每次搜索完成后，把评分达到要求（可按客户类型筛选）的新线索 / 达人自动加入。会自动跳过：没有公开邮箱的（推测的 info@ 不发）、邮箱域名不能收信的、退订或退信过的、已在其他序列中的；默认跳过德国、奥地利（当地法律要求 B2B 也要事先同意）。
- **发送节奏**（`lumee:outreach` 每分钟运行）：每个店铺每次最多发 1 封，两封之间至少间隔设定的分钟数，每天不超过上限（默认 40），只在对方国家的工作日、当地时间段（默认 9:00–17:00）发送；跟进时间加 0–90 分钟随机，避免整点集中发送。发送失败 1 小时后重试，连续 3 次失败停止；服务器返回 550–553（地址不存在）直接标记退信。
- **自动停止**（`lumee:outreach --replies` 每 10 分钟）：读取收件箱，对方回复（按 In-Reply-To / References 对应到发出的邮件，或发件地址匹配）就停止跟进，线索状态改为「已回复」并记录回复摘要；退信（mailer-daemon、Undeliverable 等）标记退信并加入不再发送名单；“外出自动回复”忽略。
- **合规**：每封邮件最后自动加签名、公司地址（必填）和退订链接，并带 `List-Unsubscribe` 一键退订头。退订页面先显示确认按钮（防止邮件安全扫描自动点击），邮件客户端的一键退订（RFC 8058）直接生效；店铺暂停时退订链接仍可用。
- **建议**：用公司域名邮箱并设置 SPF / DKIM；新邮箱从每天 20–30 封开始，逐步加量。
- **获客雷达每天重复搜索**：最近搜索旁的「每天自动重复…」，选中的搜索每天 06:10 重新运行一次（`lumee:repeat-lead-searches`），已有的公司不会重复，新公司成为新线索，可以接着自动加入序列。

## 多国家市场（独立站点）

后台「设置 › 市场」，代码在 `backend/app/Markets/`，规划见 [docs/MARKETS-PLAN.md](docs/MARKETS-PLAN.md)。

- **网址**：每个市场按 `/{语言}-{网址后缀}/` 访问，例如 `/es-mx/`（墨西哥站西语）、`/en-mx/`、`/de-eu/`。不带前缀的网址是默认站点（店铺货币），和以前一样。用“语言-后缀”的写法，是为了不和 `/de/` 这类语言前缀冲突。
- **币种**：市场里的价格、购物车、结账、付款都用市场货币，不是只换算显示。订单会记录 `market_id` 和下单时的汇率 `exchange_rate`；首页、数据分析、客户累计消费按这个汇率换算回店铺货币。
- **价格**：默认 = 店铺价格 × 汇率（自定义汇率优先，否则用每日汇率）×（1 + 价格调整%），再按价格尾数处理（.99 / .95 / .90 / 取整到 1、10、100、1000）。单个规格可以在商品页「市场与价格」里设置固定价格和划线价。
- **按店铺货币录入的金额**：运费、固定金额折扣、满减门槛、批发价，在市场里自动按汇率换算（`MarketContext::money()`）。礼品卡只能在发卡时的货币下使用。报价单始终使用店铺货币。
- **商品范围**：商品页可以取消勾选某个市场，这个市场的店铺里就看不到这个商品，也不能下单。
- **SEO**：每个页面输出所有市场和语言的 `hreflang`（例如 `es-MX`），`sitemap.xml` 包含所有市场的网址。
- **国家推荐**：访客在默认站点、且 CDN 告诉我们他来自某个市场的国家（`CF-IPCountry`）时，底部弹出“去本国站点”的提示。**不会自动跳转**；选择会记住一年。页脚有「国家/地区」切换。
- **语言**：店铺前台支持英、法、德、西、意、日、葡萄牙语（巴西葡语，`lang/pt.json`）和阿拉伯语（`lang/ar.json`），巴西站网址为 `/pt-br/`，阿联酋阿语站为 `/ar-ae/`。
- **从右到左（RTL）**：阿拉伯语等语言的页面输出 `<html dir="rtl">`（`Localization::dir()`），主题样式用逻辑属性（`margin-inline-start`、`text-align: start` 等），整页自动镜像；同一页里的英文行（例如还没翻译的购买保障）保持自己的方向。阿拉伯语的金额用西方数字（`ar-AE-u-nu-latn`），复数用阿语的六种形式。
- **各文字的字体**：阿拉伯语、日语等页面自动加载对应的 Noto 字体（`ThemeContext::SCRIPT_FONTS`），拉丁字母仍用主题字体。
- **金额格式**：市场里的金额按“语言 + 市场第一个国家”的习惯显示（PHP 用 intl 的 NumberFormatter，前台 JS 用 Intl.NumberFormat，两边一致）：巴西 `R$ 200,90`、德国 `36,00 €`、墨西哥西语 `$1,601.98`、英语 `MX$800.99`。默认站点保持 `$40.00` 不变。
- **按市场装修**：见下面「各市场的店铺装修」。规划见 [docs/STOREFRONT-DESIGN-PLAN.md](docs/STOREFRONT-DESIGN-PLAN.md)。
- **按价格排序**：市场里的商品列表按市场价格排序。设置了市场固定价的规格，会按汇率折算回店铺货币参与排序（其他规格的市场价是店铺价乘以同一个系数，所以顺序和顾客看到的价格一致）。

## 商品采集（采集 → 清洗 → 定价 → 审核 → 批量上架）

后台「商品 › 采集」，代码在 `backend/app/Collect/`，浏览器插件在 `extension/`。

- **采集方式**：
  - 粘贴商品网址（每次最多 50 个）。
  - 整个 Shopify 店铺：读取公开的 `/products.json`，最多 500 个商品。
  - 浏览器插件：适合 1688、速卖通、Temu 等需要登录或有访问防护的网站。插件把当前页面发给后台，用的是单独的「连接密钥」，这个密钥不能登录后台。
- **能识别的数据**：Shopify 商品 JSON（包括规格、图片和店铺货币）、WooCommerce Store API、页面里的 schema.org JSON-LD（包括 ProductGroup 多规格）、Open Graph 价格标签。都识别不到时，使用插件从页面上读到的标题、大图和价格。
- **合规**：只读取公开数据。服务器请求走 `SafeFetcher`，只访问公网地址；遇到访问防护直接记为「采集失败」，不绕过。上架时图片会下载到自己的存储，不直接引用供应商的图片链接。
- **自动清洗**：
  - 去掉标题里的“2026 新款 / 爆款 / 包邮 / wholesale”等词、括号里的宣传语和 emoji，全大写的标题改成首字母大写。
  - 描述只保留基本排版，去掉脚本、链接和行内事件。
  - 去掉图标、缩略图，以及供应商的品牌名。
  - 标出需要人工处理的问题：品牌词（可能侵权）、未翻译的中文、缺少图片或价格。
- **AI 优化（可选）**：使用「获客雷达 › 设置」里配置的 Claude Key，按店铺语言改写标题和描述、翻译规格、生成标签，并列出风险。每次最多 10 个商品。
- **定价规则**：售价 = 成本 × 汇率（来源货币换算成店铺货币）× 倍数 + 附加金额，再按价格尾数处理；划线价 = 售价 × 划线价倍数。规则可以按商品类型或标签匹配，从上往下第一条匹配的生效；没有规则匹配时，保留来源价格。
- **查重**：同一个来源页面（Shopify 的 `/collections/x/products/y?variant=` 会归并成 `/products/y`），或者和已有商品的标题相似度 ≥ 90%，都会标为可能重复。
- **批量上架**：在队列里执行。可以选择草稿或直接在售、加入哪些分类、在哪些市场销售（所有市场 / 按适合度自动选择 / 手动选择，见「市场适合度」），以及默认库存。上架时会记录每个规格的成本（`product_variants.cost`）和来源页面（`product_sources`）。
- 采集和上架都在队列里执行，需要运行 `php artisan queue:work`。下载外部图片需要先按上面「本地启动」第 5 步配置好 CA 证书。

## 市场适合度（每个国家看到适合它的商品）

代码在 `backend/app/Markets/MarketFit.php`（打分）和 `MarketRules.php`（规则），数据在 `product_market_fits`。

- **打分（0–100）**：四类依据，各自 0–100 再加权；没有的依据不计入，其余按比例补足。
  | 依据 | 权重 | 说明 |
  |---|---|---|
  | AI 判断 | 35 | Claude 按每个市场的需求、气候季节、文化宗教、插头尺码标准、当地价格和近期购物节打分，并用当地语言给出标签。需要「获客雷达 › 设置」里的 Claude Key。 |
  | 当地趋势 | 25 | 商品的标题、类型、标签、描述和这个市场「选品雷达」里的机会词匹配（英文会识别复数，中文按整词匹配），按机会分计算。机会里有 AI 给出的价格区间时，还会比较市场售价。 |
  | 本市场表现 | 30 | 近 30 天在这个市场的浏览、加购、订单，和这个市场表现最好的商品比较。市场总浏览少于 50 次时不计入。 |
  | 规则 | 10 | 插头规格（美规 / 英规 / 欧规 / 澳规）和当地插座是否一致；季节（南北半球、热带和海湾国家没有冬季）；当地禁售（海湾国家的酒类和猪肉制品、部分国家的电子烟）；当地节日（斋月、感恩节、排灯节、亡灵节等）。 |
- **不能卖**：插头不符、当地禁售时，分数最高 15 分。
- **采集时**：每个采集的商品都会自动按规则和当地趋势打分（不调用 AI），列表里每个商品下面显示各市场的分数，鼠标移上去可以看原因和当地标签。「AI 优化」时会同时让 AI 判断市场；也可以勾选后点「AI 判断市场」（一次最多 10 个）。
- **按适合度上架**：上架时「销售市场」选「按适合度自动选择」，只在分数不低于设定值（默认 50）的市场销售。还没有分数的市场照常销售。默认站点始终销售。
- **商品页**：「市场与价格」里显示每个市场的分数、各项依据和原因，可以「重新评估」或「AI 判断」。商品列表勾选后也可以「AI 判断市场」。
- **店铺前台**：「精选商品」模块（不指定分类时）和「商品标签页」的「适合本市场」按这个市场的分数排序：50 分以上的先显示，然后是新品，低于 40 分的放最后。「本市场热卖」销量不够时，也用这个顺序补足。默认站点（没有市场）仍然按新品排序。
- **每天更新**：`lumee:market-fit` 每天 04:55 重新计算所有商品（不调用 AI，沿用上次的 AI 判断），因为浏览、订单、趋势和季节会变化。手动添加的商品在第二天自动打分，或者在商品页点「重新评估」。

## 引流：广告商品目录 · SEO 落地页 · 达人合作

**广告商品目录**（代码在 `Storefront/FeedController.php`，网址在「设置 › 广告追踪」里复制）
- 三个平台：`/feeds/google.xml`（Google Merchant Center）、`/feeds/meta.xml`（Meta 商品目录，和 Google 同样的 RSS 格式，库存状态用 Meta 的写法）、`/feeds/tiktok.csv`（TikTok 商品目录）。
- 每个国家站点有自己的商品源，例如 `/es-mx/feeds/tiktok.csv`：只包含这个市场销售的商品，价格用市场货币（含市场固定价和促销价），链接指向这个站点。
- 三个自定义标签，可以在广告里按标签分组出价：
  - `custom_label_0`：这个市场的适合度（`fit-high` ≥ 70 / `fit-medium` ≥ 50 / `fit-low` / `fit-unknown`；默认站点是 `default-site`）。
  - `custom_label_1`：测款结果（`hot` 等，没测过是 `untested`）。
  - `custom_label_2`：毛利（`margin-high` ≥ 50% / `margin-mid` ≥ 30% / `margin-low`，没有成本是 `margin-unknown`），按店铺价格和成本计算。

**SEO 落地页**（「营销 › SEO 落地页」，代码在 `app/Marketing/SeoPages.php`）
- 一个市场 + 一个关键词 = 一个页面，用这个市场的语言，网址是 `{站点前缀}/s/{网址}`，例如 `/es-mx/s/fundas-de-silicona-mx`。
- 从「选品雷达」里有搜索需求、还没有页面的关键词一键生成，也可以手动输入关键词。
- 页面展示标题、类型或标签匹配关键词的商品（英文会识别复数），这个市场适合度高的排在前面；也可以固定展示哪些商品。
- 填了 Claude Key 时，AI 用当地语言写网页标题、描述、介绍和常见问题（不编造价格、认证和物流承诺）；没有时用简单模板（英、西、葡、法、德、意）。
- 匹配的商品少于 2 个时不能发布（内容太少的页面会影响搜索排名）。新生成的页面是草稿。
- 发布后自动加入 `sitemap.xml`。每个页面只属于一个站点：不输出其他语言的 hreflang；从其他站点访问会 301 跳转到它自己的站点。常见问题输出 FAQPage 结构化数据。
- 介绍只保留段落、列表、加粗等简单格式，链接、属性和脚本会被去掉。

**达人合作**（「营销 › 达人合作」，代码在 `app/Marketing/Creators.php`）
- 按领域关键词和国家找 Instagram、TikTok、YouTube 达人：通过 SerpApi 的 Google 搜索结果找公开主页（和获客雷达共用 Key，每次最多 9 次搜索）。帖子、视频链接会被跳过。不会登录或抓取社媒网站本身。
- 配置了 Instagram Business Discovery（获客设置）时，Instagram 商业 / 创作者账号会补全准确的粉丝数、简介和官网。
- 打分（0–100）：粉丝量最多 35 分（1 万–10 万的腰部达人最高，超大号费用高、转化低，分数较低）；简介和领域相关最多 30 分；有邮箱 20 分、有 WhatsApp 10 分。
- 「写邀请」：用达人所在国家的语言写合作邀请（免费寄样品 + 默认佣金比例 + 粉丝专属折扣码），AI 写的附中文翻译；没有 Claude Key 时用模板（英、西、葡）。
- 状态：新发现 → 已联系 → 已回复 → 已合作 / 不合作。「转为推广员」会在「联盟营销」里创建推广员，推广码默认用达人账号名，推广链接是 `/?ref=推广码`。

## 广告效果（ROAS · 每单成本）

「数据分析 › 广告效果」，代码在 `app/Analytics/AdReport.php`、`AdSpendImport.php`。

- **访问来自哪个平台**：每次访问记录广告平台（`analytics_sessions.ad_platform`）：先看点击 ID（gclid / gbraid / wbraid → Google，fbclid → Meta，ttclid → TikTok，msclkid → Bing），再看 `utm_source`，最后看来源网站。是否付费仍由 `source` 判断：有付费 `utm_medium`（cpc 等）或 Google / TikTok / Bing 的点击 ID 算广告访问；Meta 的 fbclid 也出现在普通帖子链接里，所以 Meta 广告请在链接上加 `utm_medium=cpc`（或 paid_social）。
- **花费**：上传或粘贴广告平台导出的 CSV（Google Ads、Meta 广告管理工具、TikTok 广告管理平台、Microsoft Ads 等），按天细分。
  - 中英文列名都能识别：日期、广告系列、费用 / Amount spent、货币、国家/地区、展示次数、点击次数。
  - Google Ads 报表开头的标题行、UTF-16 / Tab 分隔、千位分隔符、总计行都能处理。
  - 金额按汇率换算成店铺货币（同时保留原币金额）。有国家列时自动对应到销售那个国家的市场。
  - 同一天、平台、市场、广告系列的数据重复导入会覆盖，不会重复计算。也可以手动添加一行。
- **归因**：订单算给下单那次访问的来源；如果那次是直接访问（输入网址、书签），就算给同一访客 7 天内最近一次非直接访问。销售额 = 已付款订单金额 − 退款，换算成店铺货币。
- **报表**：按平台、国家站点、广告系列（`utm_campaign` 和报表里的广告系列名称对应，不区分大小写）显示花费、广告访问、订单、销售额、ROAS（销售额 ÷ 花费）、每单成本、转化率、点击单价，以及这些平台不花钱的自然流量订单。
- **建议**：花了预算却没有订单的广告系列、ROAS 低于 1 的国家、两个平台 ROAS 相差一倍以上时转移预算、某个平台自然流量已经出单但还没投广告。
- 没有直接连接广告平台的接口（需要各平台的 OAuth 授权和应用审核），花费通过导出的报表导入。

## 内容工坊（品牌化）

后台「商品 › 内容工坊」，代码在 `backend/app/Content/`。商品页还有一张「内容质量」卡片。

- **品牌规范**：品牌定位、目标人群、语气、禁用词、标题命名规则和长度、主图比例（3:4 / 4:5 / 1:1）、背景色、留白、每个商品至少几张图、详情页模块和顺序、上架标准分。保存在 `stores.settings.brand_kit`。
- **内容分（0–100）**：标题 20 分 · 图片 30 分 · 描述 20 分 · 属性 15 分 · 翻译 10 分 · SEO 5 分。每一项扣分都写明原因，例如“标题全是大写”“主图比例和品牌规范（3:4）不一致”“还没有翻译：Español”。翻译检查覆盖店铺发布的语言和所有市场的语言。分数存在 `products.content_score`，列表从低分往高分排。
- **AI 改写**：用获客雷达里配置的 Claude Key，按品牌规范生成某个语言的标题、分模块描述和 SEO 文案。先给出建议，不会直接保存；在对比窗口里修改后再采纳。默认语言写回商品本身，其他语言写进翻译。每次采纳前，旧内容都会存入历史版本，可以恢复。
- **统一图片**：用 GD 处理，不需要外部服务。先裁掉浅色白边，再按品牌比例、背景色和留白，生成高 1600px 的 WebP。原图会保留，可以随时还原；每次都从原图开始处理，图片不会越处理越差。可以选择先用 remove.bg 抠图，需要店铺自己的 API Key，按张计费，加密保存。
- **上架标准**：设置了最低分时，采集的商品即使选择「直接在售」，分数不够也会存为草稿，并在采集列表里注明原因。
- **AI 场景图 / 模特图**（`SceneImages`）：在品牌规范里填写图片生成服务的 API Key（目前接入 OpenAI `gpt-image-1`，加密保存）和每月额度（默认 50 张）。商品页「内容质量」卡片里选一张实拍图和场景（生活场景、棚拍、平铺、模特上身 / 手持、节日礼品），可以补充要求。
  - 提示词要求商品本身保持实拍的样子（颜色、形状、材质、文字和 logo 不变），只生成周围的场景，并带上品牌定位、目标人群和背景色。
  - 生成的图加在商品图片的最后，标记为 AI 生成（`processed.ai = scene`），上架前需要人工确认和实物一致。
  - 服务商可以替换：实现 `App\Content\ImageGenerator` 接口，加到 `SceneImages::PROVIDERS`。

## 测款（Test & learn）

后台「商品 › 测款」，代码在 `backend/app/Testing/`。商品页还有一张「A/B 测试」卡片。

- **数据**：每次商品浏览和加购，都按市场（`market_id`，0 表示默认站点）和日期记入 `product_market_stats`；订单和销售额从订单表统计，按下单时的汇率换算成店铺货币。爬虫和预加载请求不计入。
- **判断**：在测款周期（默认 14 天）里，和店铺自己的平均加购率比较：
  - 潜力款：浏览量够，且加购率 ≥ 平均的 2 倍；或者已经有 3 单。
  - 滞销：测满一个周期，浏览量够，0 订单，且加购率不到平均的一半。
  - 流量不足：上架 3 天以上，几乎没人看。
  - 观察中：其他情况。
  每种判断都附带下一步建议。可以按市场分别看，也可以看全部在售商品。规则在「测款规则」里修改（`stores.settings.testing`）。每天 04:40 运行 `lumee:test-and-learn`，把判断结果存到 `products.test_status`。
- **批量操作**：加入（手动）分类、在所有市场销售、转为草稿、下架归档。
- **站内搜索词**：记录每次搜索和结果数量（`search_terms`，按市场区分）。「搜了但没找到」列出买家想要、店里还没有的商品。
- **A/B 测试**：测试另一张主图或另一个标题。每个访客按访客 ID 固定分到 A 组或 B 组，每次看到的都是同一个版本；分别统计两组的浏览和加购。
  - 每组至少 100 次浏览，且双比例 z 检验 p < 0.05，才判定胜出。
  - 采用 B 时：标题写回商品（旧标题存入历史版本），图片 B 变成主图。
  - 标题测试只在店铺默认语言下进行。

## 选品雷达

后台「商品 › 选品雷达」，代码在 `backend/app/Research/`。

- **发现机会**：从店铺自己的数据里找（近 30 天，按市场分开）：
  - 被搜索 ≥ 2 次、却没有结果的词（搜了没找到）。
  - 被搜索 ≥ 5 次的热门词。
  - 测款里出现潜力款的商品类型。
  
  也可以手动添加关键词，并选择对应的市场。
- **导入其他工具的数据**（`ExternalImport`）：从 TikTok Creative Center、Keepa、Helium 10、Jungle Scout、Google 关键词规划师等导出 CSV，上传或粘贴。
  - 列名中英文都能识别：关键词 / hashtag、热度（搜索量 / 播放量 / 发布量 / 销量）、增长率、价格、卖家数。“1.2M”“12K”“1.2万”“+85%”“$299” 都能读。没有表头时，按每行一个关键词处理。
  - 导入的数据存在 `signals.external`，计入需求、趋势和竞争分；同一个机会如果也查了 Google Trends 和 Shopping，以 SerpApi 的数据为准。
  - TikTok 没有公开的趋势接口，Keepa、Helium 10 需要付费账号，所以用导出文件对接，不直接调用它们的接口。
- **外部数据（可选）**：使用店铺自己的 SerpApi Key（加密保存；也可以在 `.env` 里配置平台统一的 `SERPAPI_KEY`）。每个机会查两次：
  - Google Trends：该市场国家近 3 个月的搜索热度，近 4 周和之前 4 周相比的变化。
  - Google Shopping：该国家有多少卖家、最低价 / 中位价 / 最高价。价格里只有“$”时，按市场货币算（例如墨西哥是比索）。
  
  只通过官方接口获取，不抓取网页。
- **评分（0–100）**：需求 30 · 趋势 25 · 竞争 20 · 价格匹配 10 · AI 适合度 15。缺少某项数据时，按其余几项重新加权；每一项的分数都能看到。
- **AI 市场分析**：使用获客雷达里配置的 Claude Key。综合店铺定位、已有品类和上面的数据，给出：适合度、中文结论、建议售价区间、当地搜索词、标题参考、风险、旺季，以及去 1688（中文）和 AliExpress（英文）用的搜索词。每次最多分析 5 个。
- **找货**：详情里有 1688、AliExpress、Amazon、Google Shopping 的搜索链接，由商家自己打开；找到合适的商品后，用插件或「商品采集」采进来。
- **状态**：新发现 → 观察 → 找货中 → 测款中 → 已成功 / 放弃；可以写备注。

## 市场本地化（主题文案、关税、税号、尺码、活动日历、当地支付）

在「设置 › 市场」里点市场的「本地化」，代码在 `backend/app/Markets/`（MarketSettings、Presets、ShoppingCalendar）、`app/Catalog/SizeCharts.php` 和 `app/Support/TaxIds.php`。

- **店铺装修**：本地化面板里的「店铺装修」直接打开这个市场的主题编辑器（见「各市场的店铺装修」）。以前存在 `markets.settings.theme` 里的十个字段，已由迁移 `2026_11_25_100000_market_themes` 搬进主题的市场层，前台效果不变。
- **区域预设**：套用预设时，当地语言的公告和购买保障直接写进这个市场在线主题的装修（草稿和线上同时更新）。
- **区域预设**：美国 / 欧洲 / 拉美 / 东南亚。一键设置价格尾数、当地语言的公告和购买保障、关税处理方式，并给出推荐的支付方式和注意事项。套用后可以继续修改。
- **关税**（`markets.settings.duties`），有四种方式：
  - 不处理。
  - 已含在售价里（结账页注明“关税已包含”）。
  - 结账时收取：按折扣后的商品金额 × 税率，计入 `orders.duty_total`；商品金额不超过免税额时不收。订单页、邮件、后台都会显示这一行。
  - 买家收货时付（结账页提示“快递可能在派送时收取”）。
  
  税率要商家自己填。
- **税号**：寄往巴西、阿根廷、智利、哥伦比亚、秘鲁时，结账页要求填写税号。巴西的 CPF / CNPJ 会做校验位检查。税号存在收货地址里，后台订单页可以看到。
- **尺码**：商品选择尺码类型（女鞋 / 男鞋 / 戒指 / 服装），规格里的尺码按美码填写。各市场的商品页会在尺码旁显示当地尺码（欧码、英码、巴西码、墨西哥码），并提供尺码对照表。
- **当地支付**：新增 Stripe 的 OXXO、Boleto、EPS、Przelewy24、GrabPay、PayNow、PromptPay。只要店铺货币或任意一个市场的货币支持，就可以在收款设置里开启。结账时按订单货币筛选可用的支付方式。
  - OXXO、Boleto 这类“先下单、再去便利店或银行付款”的方式：Stripe 结账完成时订单保持“待付款”，订单页提示买家按收到的付款单付款；买家付款后（Stripe `checkout.session.async_payment_succeeded`）自动标记已付款；付款单过期没付（`async_payment_failed`）时自动取消订单、回补库存并通知买家。Stripe 后台的 webhook 需要勾选这两个事件。
- **货到付款**（`CashOnDeliveryGateway`，`markets.settings.cod`）：在市场本地化的「当地支付」里按市场开启，可以设置手续费和订单金额上限（市场货币）。
  - 只在这个市场里出现，只能寄到市场的国家，必须填电话，订阅商品和纯数字商品不能用。
  - 手续费记在 `orders.payment_fee`，结账页选择货到付款时才加到合计里；订单页、邮件、后台都会显示。
  - 订单是「待付款」，收到货款后在后台标记已付款。
- **分期付款**（`App\Payments\Installments`，`markets.settings.installments`）：墨西哥比索（MSI）和巴西雷亚尔（parcelamento）市场可以开启。
  - 商品页显示“或分 N 期，每期 X”（可以选免息或不免息的说法），切换规格时自动更新，低于最低金额不显示。
  - 用 Stripe 付款时，Checkout 打开银行卡分期（`payment_method_options[card][installments][enabled]`），买家在付款页选择期数。需要该国家的 Stripe 账户，并在 Stripe 后台开通分期。
- **Stripe 金额校验**：发给 Stripe 的明细行（商品、运费、税、进口关税）加起来不等于订单应付金额时（例如礼品卡抵扣了一部分），改为按应付总额收一行，保证收款金额和订单一致。
- **活动日历**：列出每个市场未来半年的购物节点，比如黑五、网络星期一、Buen Fin、Hot Sale、巴西情人节、斋月和开斋节、9.9 到 12.12、圣诞。每个节点注明从哪天开始准备，以及准备建议。

## B 端加深（按市场批发、批发目录、采购和供应商端）

代码在 `backend/app/B2B/Catalogs.php`、`app/Supply/Purchasing.php`、`app/Pricing/PriceLists.php`。

- **按市场的批发价格表**：价格表可以指定市场（`price_lists.market_id`）。这个市场的批发客户只用它，价格直接按该市场货币填写，不换算；不指定市场的通用价格表在各市场里按汇率换算。
- **快速下单**（`/wholesale/order`，只对批发客户开放）：按“SKU, 数量”一行一条粘贴，按批发价、起订量和阶梯价加入购物车；找不到或不能购买的行会逐行说明原因。
- **批发目录**（「商品 › 批发目录」）：私密链接 `/wholesale/catalog/{token}`，按某个市场的货币和价格表展示零售价、批发价、起订量、阶梯价和库存。
  - 同一个链接加上 `.json` 或 `.csv`，就是给分销商导入用的数据接口。
  - 可以只包含某个分类，可以设置到期日，能看到被打开的次数。
  - 获客雷达的线索详情里有「批发目录链接」：按线索所在国家匹配市场和价格表，生成后复制，可以直接贴进开发信。
- **分销商下单接口**：在批发目录卡片里打开「下单接口」，会生成单独的密钥（目录链接可能被转发，所以下单不能只凭链接）。
  - `POST /wholesale/catalog/{token}/orders`，请求头 `Authorization: Bearer {密钥}`，内容是 `email`、`po_number`（可选）、`shipping_address`、`items`（`variant_id` 或 `sku`，加 `quantity`）。
  - 价格、起订量、阶梯价都按目录的市场和价格表计算，订单用市场货币，记录市场和汇率，库存马上扣减。
  - 订单进入后台「订单」，状态是待付款，来源为 `wholesale_api`：确认运费和付款方式后再发货。同一个采购单号重复提交会返回第一次的订单，不会重复下单。
  - `GET /wholesale/catalog/{token}/orders/{订单号}` 查询付款、发货状态和物流单号。
  - 关闭接口或重新生成密钥后，旧密钥立即失效。
- **采购**（「商品 › 采购」）：
  - 补货建议：近 14 天销量折算成 30 天的需求，减去库存和在途数量；测款中的潜力款库存不足时也会提醒。建议按供应商分组。
  - 采购单：草稿 → 发给供应商（有邮箱时发邮件通知）→ 供应商确认 / 发货 → 收货入库。入库时库存增加，库存记录里记为“采购入库”，规格成本更新为采购价。
- **供应商端**：每个供应商一个私密链接 `/supplier/{token}`，不需要注册账号。供应商可以：
  - 查看采购单（不显示我们的成本和售价）。
  - 确认交期、填写物流单号。
  - 推荐新品，新品会进入「商品采集」的待审核列表（来源标为供应商）。
  
  可以随时重新生成链接，旧链接立即失效。

## 后台导航

左侧菜单（`admin/src/components/SidebarNav.vue`）采用常见 SaaS 后台的做法：
- 模块按工作分组，每个模块只占一行：

  | 分组 | 模块 | 子页面 |
  |---|---|---|
  | — | 首页 | |
  | 销售 | 订单 | 弃单、订阅、退货 |
  | | 客户 | 隐私请求 |
  | | B2B 批发 | 公司、询价单、批发价、批发目录、获客雷达 |
  | 商品与货源 | 商品 | 商品分类、评论、礼品卡 |
  | | 选品上新 | 选品雷达、采集、内容工坊、测款 |
  | | 采购 | |
  | 增长 | 营销 | 自动化、联盟营销、积分、追踪代码 |
  | | 折扣 | 自动折扣 |
  | | 数据分析 | |
  | 销售渠道 | 在线商店 | 页面、博客、导航菜单、网址重定向、翻译 |
  | 底部 | 应用、设置 | |

- 进入某个模块后，才展开它的子页面。
- 选中的项目用浅灰底色和绿色图标标示。
- 子页面按各自路由的 `meta.perm` 过滤；没有权限打开模块首页时，点模块会进入第一个能打开的子页面，全部不能打开时整个模块隐藏。
- 新增页面时，挂到对应模块的 `children` 里；详情页用路由的 `meta.menu` 指向它所属的列表页。

## 商家后台中英文

- **切换语言**：后台右上角用户菜单 →「Switch to English / 切换到中文」；登录页底部也可以切换。
  - 选择保存在浏览器里。第一次打开时，中文浏览器显示中文，其他语言的浏览器显示英文。
  - 切换后页面会刷新。Naive UI 自带的文字（日期选择器、分页、空状态）也会一起切换。
- **前端**（`admin/src/i18n`）：
  - 界面文字以中文为准，写作 `t('中文')`，英文翻译在 `en.json`。
  - 带变量的写法：`t('共 {0} 个', [n])`。模板中可以直接用 `t()`。
  - 开发环境下切换到英文时，没有翻译的中文会在浏览器控制台警告一次。
  - 检查漏翻：`cd admin && node scripts/i18n-missing.mjs`，列出 `en.json` 里还没有英文的 `t('中文')`，有遗漏时退出码为 1，可以放进 CI。
- **后端**：后台请求带有 `X-Admin-Locale: zh_CN | en` 请求头，由 `SetAdminLocale` 中间件设置语言。
  - 错误提示统一写成 `__('中文')`，英文在 `backend/lang/en.json`。
  - 新增文字时，要同时加到 `lang/en.json` 和 `lang/zh_CN.json`（后者是原文对原文）。否则中文后台会回退显示英文。
  - 常量和配置里的文字（主题编辑器字段、套餐名称、权限、取消原因等）在返回给后台时用 `App\Support\Tr` 翻译。
- **不翻译的内容**：
  - 商家自己的数据，例如运费区域名称、商品名。
  - 以前就存进数据库的订单动态：常见的几条会显示英文，带附加信息的保持原文。
- **发给商家的邮件**跟随收件人上次使用后台的语言（保存在 `users.locale`）：
  - 新订单提醒、账单提醒发给店主，使用店主的语言。
  - 员工邀请使用邀请人当前的语言。
  - 发给买家的邮件仍然按买家下单时的语言发送。

## 多语言（店铺前台）

- **语言设置**（设置 → 语言）：
  - 选择默认语言，再勾选要发布的其他语言。
  - 默认语言的网址没有前缀，其他语言带前缀，例如 `/fr/products/…`、`/ja/cart`。未发布的语言返回 404；用默认语言前缀访问（如 `/en/…`）会 301 跳转到不带前缀的网址。
  - 支持的语言写在 `config/lumee.php` 的 `languages` 里：English、Français、Deutsch、Español、Italiano、日本語。
- **系统文字**：店铺里的按钮、购物车、结账、账户页面、提示信息、表单验证消息、买家邮件都已翻译好。
  - 翻译文件在 `backend/lang/{语言}.json` 和 `lang/{语言}/validation.php`，英文为原文。
  - 新增一种语言：添加这两个文件，并在配置里加上该语言即可。
- **商家内容翻译**（在线商店 → 翻译）：左右对照编辑，左边是原文，右边填译文。
  - 可翻译：商品（名称、描述、类型、规格名和规格值、SEO）、商品分类、页面、导航菜单、店铺装修里的文字、运费名称、线下付款名称和说明。
  - 没有翻译的字段显示默认语言；清空译文即恢复显示原文。
- **怎么实现的**（`App\I18n\Localization`）：
  - 店铺前台用非默认语言时，模型会自动返回译文，模板不需要改动。
  - 中间件（`SetStorefrontLocale`）把页面里的站内链接和跳转地址都加上语言前缀，买家点击链接时会一直停留在当前语言。
  - 商家后台和 API 始终看到原文。
- **SEO**：
  - 页面带 `hreflang` 标签，同时列出每种语言的版本和 `x-default`；canonical 指向当前语言的网址。
  - sitemap.xml 包含每种语言的网址。
  - 页脚有语言切换。
- **订单**：
  - 订单会记录买家下单时使用的语言（`orders.locale`）。订单确认、发货、退款等邮件用这种语言发送，邮件里的链接也带语言前缀。
  - 订单中的商品名、规格、运费名称保存为默认语言，商家发货时看到的是原文。
  - 给商家的新订单提醒仍然是中文。

## 平台计费与运营后台

商家付给 Lumée 的费用：套餐月费或年费，加上按订单收取的交易佣金。套餐定义在 `backend/config/plans.php`（价格单位为美分），改这个文件即可调整价格和权益。

| 套餐 | 月付 | 年付 | 交易佣金 | 成员上限（含所有者） | 自有域名 |
|---|---|---|---|---|---|
| 免费试用（14 天） | — | — | 0 | 4 | 可以 |
| 入门版 | $9 | $90 | 2% | 1 | 不可以 |
| 基础版 | $29 | $290 | 1% | 4 | 可以 |
| 专业版 | $79 | $790 | 0.5% | 15 | 可以 |

**店铺状态**（`App\Billing\Billing`）：
- 试用中、付费中、扣款失败（宽限 7 天）这三种状态下，店铺正常营业。
- 已到期（试用结束未订阅，或订阅已结束）、已暂停（被运营暂停）时：
  - 店铺前台显示「暂时关闭」（503）。买家仍然可以打开已有订单的状态页。
  - 商家后台除「设置 → 套餐与账单」外，其余接口都返回 402，后台会自动跳到账单页。
  - 商品和订单数据都会保留，订阅后立即恢复。

**订阅**：
- 只有店铺所有者能更改套餐，员工只能查看。
- 后台在试用剩 7 天内、扣款失败、到期时都会显示提醒条。
- 支付方式：
  - **Stripe**（生产环境）：订阅走 Stripe Checkout 托管页面。剩余的试用天数会保留，试用结束后才开始扣费。
    - 升级、降级会按剩余时间自动计算差价；取消订阅在本期结束时生效，期间可以随时恢复。
    - 状态以 Stripe 为准，由 Webhook 同步：`checkout.session.completed`、`customer.subscription.*`、`invoice.paid`、`invoice.payment_failed`。它们使用同一个 `/webhooks/stripe` 地址，需要在 Stripe 后台勾选这些事件。
  - **测试模式**（`.env` 中设置 `LUMEE_TEST_BILLING=true`，本机已开启）：选择套餐后立即生效，不会真实扣款，方便在本地体验完整流程。生产环境必须关闭。
- 限制：
  - 降级到成员上限更低的套餐时，需要先移除多出来的员工。
  - 没有自有域名权益的套餐不能绑定新域名，已绑定的自有域名会跳转到 lumee 二级域名。

**交易佣金**（`App\Billing\FeeLedger`）：
- 付费套餐的订单在付款时按当时的费率记一笔佣金；订单退款时，退款部分的佣金同时扣回。
- 试用期间的订单和测试支付的订单不收佣金。
- 开启 Stripe Connect 后，信用卡订单的佣金在付款时直接作为 application fee 扣除。
  - 这类佣金记录的 `collected_at` 有值，不会进入月度账单。
  - 退款时 Stripe 会按比例退回佣金，对应的扣回记录也标记为已收取。
- 每月 1 日由 `lumee:bill-fees` 合并结算，按汇率换算成美元生成账单：
  - Stripe 订阅的商家：佣金加到下一期套餐账单里一起扣款；
  - 测试模式：直接记为已支付；
  - 其他情况：账单保持「待支付」，由运营线下收款后标记为已支付。

**定时任务**（需要运行 `schedule:work` 或 cron）：
- 每天 `lumee:billing-daily`：测试模式和平台赠送的订阅到期后续期或结束；试用剩 3 天时给所有者发提醒邮件（每家店只发一次）。
- 每月 `lumee:bill-fees`：结算交易佣金。

**运营后台**（`/ops`，只有平台管理员能进入）：
- 开通账号：`php artisan lumee:platform-admin 邮箱`，取消用 `--revoke`。开通后，后台右上角用户菜单里会出现「平台运营后台」。
- **平台概览**：MRR（年付按月折算）、近 30 天收入、待结算佣金、各状态店铺数量、套餐分布、近 30 天开店趋势。
- **店铺**：按状态筛选，可以按店名或店主邮箱搜索。店铺详情页可以执行以下操作：
  - 延长试用；
  - 赠送套餐：可设有效期，原因必填，会记录操作人；
  - 暂停店铺：需要写原因，商家能看到；之后可以恢复。
- **平台账单**：所有套餐费和佣金账单，线下收到的款可以标记为已支付。

## 订单管理：退款 · 取消 · 订单动态

- **退款**（订单页右上角「退款」）：
  - 可以选择退哪些商品、每种退几件，以及是否退运费。系统会按折扣比例算出建议金额，金额可以手动修改。
  - 可以选择是否把商品加回库存、是否给买家发退款邮件。
  - 可以多次部分退款；全部退完后，订单状态变为「已退款」。
  - Stripe 订单会调用 Stripe Refund API 原路退回。如果 Stripe 返回失败，系统不会记录这笔退款。
  - 银行转账订单只做记录，需要商家线下把钱退给买家，弹窗里会提示。
- **取消订单**（「更多 → 取消订单」）：
  - 需要选择取消原因。
  - 已付款的订单可以同时全额退款；也可以只取消不退款，之后再单独退款，这种情况下库存不会被回补两次。
  - 未付款的订单会变为「已作废」，并归还折扣码的使用次数。
  - 已发货的订单不能取消，只能退款。
  - 订单取消后，如果买家仍然完成了付款（例如一直开着 Stripe 付款页），系统会记录这笔付款并提醒商家退款。
- **订单动态**：下单、付款、发货、退款、取消、修改物流信息都会记入时间线，员工也可以添加内部备注。
- 发货后可以修改物流信息，并选择是否重新给买家发送发货通知。
- **物流跟踪**（17TRACK，`App\Shipping\PackageTracking`）：
  - 开启方式：
    - 在 `.env` 里填写 `SEVENTEEN_TRACK_KEY`。
    - 在 17TRACK 后台把 webhook 地址设为 `https://<平台域名>/webhooks/17track`。
    - 不填写 key 时不会调用任何接口，买家只看到 17TRACK 的查询链接。
  - 开启后：
    - 发货时自动把运单号注册到 17TRACK，承运商由 17TRACK 自动识别。
    - 状态更新由 webhook 推送（签名为 `sha256(请求体 + "/" + key)`）。
    - `lumee:tracking-sync` 每小时补查一次：只查发货 60 天内、还没签收、3 小时内没查过的订单。
  - 订单记录最新状态（已揽收、运输中、派送中、待自提、派送失败、已签收、物流异常、长时间无更新）、承运商和最近 50 条物流轨迹：
    - 买家订单页显示进度条和最近的物流事件。
    - 后台订单页显示状态、承运商、签收时间和物流事件，并提供「刷新」按钮。
  - 签收后记录签收时间（`orders.delivered_at`），并给买家发「已签收」邮件（可以在邮件通知里关闭）。
  - 出现物流异常或派送失败时，会写入订单动态提醒商家。
  - 修改运单号后，会清空旧的物流进度并重新注册。
- **统计口径**：首页和数据分析中的销售额是扣除退款后的净销售额，已取消的订单不计入。
- 订单列表新增「退款」和「已取消」两个标签页。

## 后台常用工具：建单 · 导出打印 · 客户 · 库存 · 重定向

- **手动创建订单**（订单 › 创建订单，`ManualOrderController`）：适用于电话、聊天、批发或补发订单。
  - 商品可以改单价（例如批发价，或补发时设为 0），可以加折扣（金额或百分比，带原因）、自定义运费，以及按店铺设置计算税费。
  - 付款状态选「已收款」或「待付款」（货到付款、稍后转账）。
  - 库存像普通订单一样扣减；库存不足时默认拦下，勾选后才允许超卖。
  - 默认不给买家发邮件，勾选后才发订单确认邮件。
  - 订单会标记来源为「后台」（`orders.source = admin`），并记录是谁创建的。
- **导出与打印**：
  - 订单列表的「导出」按当前标签页和搜索条件导出 CSV，一行一个订单，最多 5 万行。
  - 订单详情「更多」里可以打印发票和装箱单。
  - 所有 CSV 都带 BOM（Excel 直接打开不乱码），并会处理以 `=`、`+`、`-`、`@` 开头的单元格，防止公式注入。
- **客户管理**：
  - 列表：可按标签、购买次数（未下单 / 1 单 / 回头客）、营销订阅状态筛选，可按消费金额、订单数排序。勾选后可以批量添加或移除标签，也可以按当前筛选条件导出 CSV。
  - 客户详情：消费金额、订单数、客单价、最近下单时间、订单记录、默认地址。可以编辑标签和只有员工能看到的备注。
  - 营销订阅开关：后台修改时，来源记为「商家后台」。
- **库存记录**（`inventory_adjustments`）：每次库存变动都会记下变动数量、变动后的结余、原因、关联订单和操作人。
  - 记录的原因包括：创建商品、编辑商品、手动调整、下单、退款退回、取消订单退回、CSV 导入、API、从其他店铺复制。
  - 商品页的「库存记录」卡片可以按数量增减，或直接设为盘点数，并填写原因；调整立即生效。
  - 下单、退款、取消改用原子操作（`Services\Inventory::change`）；编辑商品、导入和 API 保存时，由规格模型的保存事件自动记录。
- **网址重定向**（在线商店 › 网址重定向）：原路径 → 新地址，301 跳转。
  - 只有原路径打不开（404）时才会跳转。原路径不区分大小写，`?` 后面的参数会被忽略；`/fr/旧路径` 也能匹配。
  - 目标只能是站内路径或 http(s) 网址；不能重定向首页。
  - 支持 CSV 导入和导出，可以直接导入 Shopify 导出的重定向文件。会统计每条重定向的访问次数。
  - 实现：中间件 `store.redirects`，加上一个 fallback 路由，让未知路径也能先查重定向。

## 礼品卡 · 退货 · 后台安全

- **礼品卡**（商品 › 礼品卡，`App\GiftCards\GiftCards`）：
  - 发放：可以自定义面值、代码（默认随机 16 位，不含容易看错的 0/O/1/I）、有效期、收件人和留言，并可以发邮件给收件人。完整代码只在发放时显示一次，之后列表里只显示后 4 位。
  - 使用：买家在购物车的「折扣码或礼品卡」框里输入代码，可以和折扣码同时使用。结账时从应付总额里扣除，余额留在卡上下次用。
    - 订单的 `total` 是扣除礼品卡之后实际要付的钱，礼品卡抵扣的部分记在 `gift_card_total`。
    - 礼品卡在下单的数据库事务里加锁扣减，并发下单也不会多扣。
    - 礼品卡全额支付时，订单直接标记为已付款（付款方式 `gift_card`），不经过支付网关。
  - 订单取消时余额自动退回。每次发放、消费、退回、手动调整都有记录，可以看到关联的订单和操作人。也可以停用礼品卡。
  - 出售礼品卡：见下面「出售礼品卡」。
- **退货申请**（订单 › 退货，`App\Returns\Returns`）：
  - 买家申请：在订单页面，对已发货、已付款、在退货期限内（默认签收后 30 天）的订单，选择商品、数量和原因提交申请。数量不能超过买到的件数减去已退款的件数；同一个订单同时只能有一个进行中的申请。
  - 商家处理：同意时会把退货说明发邮件给买家（可以设置默认说明）；拒绝时可以写明原因；收到退货后点「标记已收到」，再到订单里退款。
  - 邮件：新申请会发给商家（后台语言），处理结果会发给买家（买家购物时的语言）。
  - 退货政策（是否开启、期限天数、默认说明）存在店铺设置里。
- **两步验证**（设置 › 账户安全，`App\Security\Totp`，RFC 6238）：
  - 开启：输入密码 → 用验证器应用扫描二维码 → 输入验证码确认。确认后生成 8 个恢复码，只显示一次，每个只能用一次，数据库里只存哈希。
  - 登录：开启后，只输入密码拿不到令牌，只会得到一个 10 分钟内有效的加密凭证，再提交验证码（或恢复码）才能登录。
  - 密钥加密保存；关闭两步验证和重新生成恢复码都要输入密码。
- **操作日志**（设置 › 操作日志）：中间件 `admin.activity` 自动记录。
  - 记录：后台每个成功的修改操作和每次导出，内容包括操作人、时间、IP 和操作对象（如订单号、商品名）；登录和两步验证的开关也会记录。
  - 不记录：店铺装修的自动保存、上传和失败的请求。
  - 可以按员工和类型筛选。
- **店铺前台**：
  - 商品页底部新增「你可能还喜欢」，优先显示同分类的商品，不够时用最新商品补足。
  - 收藏夹：商品页有收藏按钮，页头有收藏图标和数量，`/wishlist` 页面列出收藏的商品。收藏记录保存在买家浏览器里（每个店铺分开），不需要登录。
  - 购物车里原来就有「再买多少免运费」的提示条。

## 积分 · 短信 · 服务器端广告事件 · 出售礼品卡

- **出售礼品卡**：在商品编辑页勾选「这是礼品卡商品」，不同面值可以用规格来做。
  - 买家付款后，每买 1 件就生成一张面值等于实付单价的礼品卡，并发邮件给买家。
  - 送给别人：商品页可以填收件人的邮箱、名字和留言（`cart_items.gift` → `order_items.gift`）。付款后礼品卡发到收件人的邮箱，邮件里带上留言；购物车和后台订单页会显示收件人。
  - 不会重复发放：按订单商品去重，同一个「已付款」事件重复处理也只发一次。
  - 只买了礼品卡的订单自动标记为已发货。
- **积分**（营销 › 积分，`App\Loyalty\Points`）：
  - 获得：有账户的顾客每笔订单付款后获得积分，默认每消费 1 元得 1 分，按实付金额计算，不含礼品卡抵扣的部分。同一订单只发一次。订单取消时扣回本单积分，但最多扣到 0。
  - 兑换：顾客在账户页或购物车把积分换成专属抵扣金（默认 100 分抵 1 元，有最低兑换数），并直接用到购物车里。
    - 抵扣金实际上是一张来源为 `points` 的礼品卡，所以可以分多次使用，订单取消时自动退回。
  - 后台：可以看积分统计和积分最多的顾客；在客户详情里可以手动增减积分并写原因。每次变动都有记录。
- **短信通知**（设置 › 邮件通知 › 短信通知，`App\Notifications\Sms`）：
  - 使用商家自己的 Twilio 账户（Account SID、Auth Token 加密保存、发送号码）。
  - 可以分别开启「订单确认」和「发货通知」短信（发货短信带物流单号），按买家购物时的语言发送。
  - 手机号：没写国家码时按收货国家补全成 E.164 格式；无法识别的号码不发。
  - 发送：通过队列发送。同一个订单、同一类型的短信只发一次。后台可以看最近的发送记录，也可以发测试短信。
- **服务器端广告事件**（营销 › 追踪代码，`App\Marketing\ServerEvents`）：
  - 订单付款后，服务器会把购买事件发给 Meta Conversions API 和 TikTok Events API（队列任务 `SendServerEvents`）。
  - 事件 ID 是 `order-#1001`，和浏览器像素发的一样，平台会自动去重。
  - 邮箱、电话、姓名、城市、邮编、国家都先做 SHA-256 哈希再发送。访问令牌加密保存，后台只显示「已保存」。
  - 支持测试事件代码；页面上显示每个平台上次发送成功还是失败，以及失败原因。

## B2B 批发（公司 · 账期 · 阶梯价 · 询价）

整套 B2B 由 `App\B2B\B2B`（当前买家、所属公司、账期、免税、店铺 B2B 设置）和 `App\Pricing\PriceLists`（价格、起订量、阶梯价）配合完成。

- **公司**（客户 › 公司）：
  - 一家公司可以有多个采购人（管理员或采购员）和多个收货地点；结账时可以一键选择公司地点。
  - 可以设置税号、账期（Net N 天）和是否免税。
  - 公司的标签决定适用哪个批发价格表，公司里的每个采购人都会用这个价格。
  - 公司详情里能看到订单、未付金额和逾期订单。
- **账期付款**：有账期的公司结账时会多一个「Pay on account（Net N 天账期）」付款选项（`TermsGateway`）。
  - 订单直接下单，记下到期日和 PO 号，等商家收到货款后点「标记为已付款」。
  - 计划任务 `lumee:payment-reminders` 每天检查，逾期后给买家发一次付款提醒；首页待办会显示逾期订单数。
  - 这个付款方式只对有账期的买家显示，不出现在店铺的收款设置里。
- **免税**：公司或单个客户可以设为免税，结账时不收税，结账页会提示。
- **起订量、倍数和阶梯价**：在批发价格表里，可以按商品设置。
  - 可设置的内容：固定价（不填就用整张表的折扣）、最低起订量、按几件的倍数购买，以及阶梯价（例如 12 件以上每件 16.5，24 件以上每件 15）。
  - 商品页会显示阶梯价表和起订规则；加入购物车和结账时都会检查。阶梯价按数量自动生效，也会和订阅优惠叠加。
- **只对批发客户可见的商品**：商品编辑页勾选后，游客和普通客户在列表、搜索、商品页、商品数据源里都看不到这个商品，也加不进购物车。
- **只对登录客户显示价格**（B2B 设置）：适合纯批发店铺。游客看到的是「登录查看价格」，无法下单。
- **批发申请**（`/wholesale`，在 B2B 设置里开启）：
  - 申请：企业填写公司名、税号、联系人、邮箱等提交申请，商家会收到邮件。
  - 批准：自动创建公司（使用默认标签和账期，可选择免税），把申请人设为公司管理员，并给对方发「设置密码」的链接（7 天有效）。已有账户的直接登录即可。
  - 拒绝：可以写原因，会发邮件告诉对方。
- **询价单**（客户 › 询价单）：
  - 批发买家在购物车里点「请求报价」，购物车内容会变成询价单。
  - 商家可以改单价和数量，设置运费、有效期和说明，然后发给买家。
  - 买家在 `/quotes/{token}` 查看并接受（可填 PO 号），系统自动生成订单：有账期的公司按账期付款，其他按线下付款。买家也可以拒绝。
  - 每一步都会邮件通知对方（商家邮件用后台语言，买家邮件用店铺语言）。
- **订单**：B2B 订单会记录所属公司和 PO 号，订单详情页会显示账期和到期提醒。手动建单的逻辑也给询价单接受时复用了。

## 批发价 · 订阅购买

- **批发价（B2B）**（商品 › 批发价，`App\Pricing\PriceLists`）：
  - 适用范围：价格表按客户标签生效，例如 `wholesale`，大小写不限。客户登录后，商品页、列表、购物车、结账和订单都使用批发价（在 `ProductVariant` 的价格读取里统一处理）。
  - 定价方式：可以全场打折，也可以给单个规格设固定价（固定价优先）。和限时折扣同时存在时，取更低的价格；原价会显示为划线价。
  - 最低起订金额：达不到时不能结账，购物车会给出提示。
  - 不受影响的：游客和没有标签的客户看到的价格不变；后台和 API 里的价格也不变。
- **订阅购买（Subscribe & save）**（`App\Subscriptions\Subscriptions`）：
  - 开启：在商品编辑页开启订阅，设置订阅优惠和配送频率（每 1–4 周，或每 1、2、3、6 个月），也可以设为只能订阅。
  - 购买：商品页显示「单次购买 / 订阅」选项。同一个商品可以同时以单次和订阅两种方式放进购物车，库存合并计算。
  - 支付方式：购物车里有订阅商品时，只能用 Stripe（保存银行卡，`setup_future_usage=off_session`，只用银行卡）或线下付款。
  - 开始：订单付款后，每种配送频率建一个订阅，并发邮件给顾客，邮件里带管理链接。
  - 续订：计划任务 `lumee:renew-subscriptions` 每小时检查到期的订阅。
    - 按订阅价生成新订单（订单来源为 `subscription`），收货地址和运费沿用首单，税费重新计算。
    - 用 Stripe 保存的卡自动扣款（支持 Stripe Connect 分账）；线下付款的订阅会生成待付款订单。
    - 扣款成功后才扣库存。
  - 失败处理：扣款失败时不留下订单，3 天后重试，并通知顾客；连续失败 3 次后自动取消。库存不足或商品下架也算失败。
  - 顾客管理：通过邮件、订单页或账户页里的链接打开 `/subscriptions/{token}`，可以跳过下一次、暂停、恢复、取消。
  - 后台管理：订单 › 订阅，可以看进行中的订阅数、每月订阅收入（估算）和扣款失败的订阅，也可以跳过、暂停、恢复、立即续订、取消。

## 到货通知 · 生日和浏览提醒 · Stripe Tax · Pix 和 UPI · 应用评价

- **到货通知**（`App\Marketing\StockAlerts`）：
  - 商品页：有规格售罄时显示「到货通知」表单，顾客留下邮箱即可（`POST /products/{handle}/notify`，每分钟最多 10 次）。同一邮箱同一规格只记一次。
  - 发送：库存从 0 变成有货时（库存记录 `Inventory::change` 或在编辑器里改库存都算），给等待的顾客各发一封邮件，用顾客当时的语言，链接直接带上规格。每个登记只发一次。
  - 这是顾客主动要求的通知，不需要营销订阅同意。后台商品编辑页会显示正在等待补货的人数。
- **生日祝福**（自动化邮件）：顾客生日当天（按店铺时区）发送，每年一次；2 月 29 日出生的顾客在平年 2 月 28 日收到。顾客在账户页填写生日，商家也可以在客户详情页填写。只发给订阅了营销邮件的顾客。
- **浏览未购买提醒**（自动化邮件）：已登录的顾客看过商品后 1、2、4、8 或 24 小时内没有下单，就发提醒，邮件里第一个商品就是他看过的那个。同一位顾客每周最多一次，下单后停止。
- **Stripe Tax（美国销售税）**（`App\Services\StripeTax`，设置 › 税费）：
  - 开启后，美国订单按邮编、城市、街道调用 Stripe Tax 计算州、县、市的销售税，结账页、手动建单和订阅续订都使用同一套计算。
  - 使用 Stripe Connect 时，按店铺自己的 Stripe 账户计算（税务登记在店铺账户里）。
  - 结果缓存 30 分钟。Stripe 出错时自动改用店铺自己设置的州税率，不会影响下单。
  - 前提：在 Stripe 后台开通 Stripe Tax，并登记有纳税义务的州。商品价格含税时不使用。
- **Pix（巴西）**：作为 Stripe 的本地付款方式提供，只在店铺货币为 BRL 时可选。
- **Razorpay（印度 UPI）**（`App\Payments\RazorpayGateway`）：
  - 只对货币为 INR 的店铺显示。买家跳到 Razorpay 付款页（Payment Links），可以用 UPI、银行卡、网银或钱包付款。
  - 回跳地址 `/checkout/razorpay/return`：先校验 HMAC-SHA256 签名，再向 Razorpay 查询付款链接，确认已付清且金额和币种一致后，订单才变为已付款。
  - 支持在后台直接退款（原路退回）。平台密钥配置在 `.env` 的 `RAZORPAY_KEY_ID`、`RAZORPAY_KEY_SECRET`。
- **应用评分和评论**：
  - 应用市场的卡片显示平均分和评价数。点开可以看评分分布和所有评价。
  - 只有安装过这个应用的店铺才能评价，每个店铺一条，可以修改或删除。
  - 开发者可以在「开发自己的应用」页面查看评价并公开回复。

## 订单风控（欺诈识别 · 黑名单）

- **风险分**（`App\Risk\RiskAnalyzer`）：每个店铺前台订单下单时都会计算风险分（0–100），30 分以上为中风险，60 分以上为高风险。风险分只是参考，从不阻止下单，也不会自动取消订单。
  - 参考信号：下单 IP 所在国家和收货国家不同（需要 CDN 提供国家，例如 Cloudflare 的 `CF-IPCountry`）、临时邮箱、首单金额超过店铺平均订单金额的 3 倍（订单不足 10 单的新店按 1,000）、同一 IP 一小时内多次下单、同一 IP 一天内换多个邮箱、同一邮箱一小时内多次下单、单个商品买 10 件以上（批发客户除外）、这个邮箱以前发生过拒付。
  - Stripe Radar：Stripe 的 `charge.succeeded` webhook 带回 Radar 的判断（偏高 +30、高 +60），会重新计算风险等级。需要在 Stripe webhook 里加上这个事件。
- **暂停发货**：高风险订单默认暂停发货，后台和开放 API 都不能发货，直到商家在订单页点「确认无风险」。订单动态会记录这两步；商家新订单邮件里会显示风险等级和原因。
- **下单黑名单**（设置 › 风控）：可以拉黑邮箱、邮箱域名或 IP。被拉黑的买家结账时只会看到「无法处理订单，请联系店铺」，后台会记录拦截次数。订单页的风险分析卡片里可以一键拉黑这个邮箱或 IP。
- **后台**：订单列表有风险列；订单详情显示风险分、每一条原因和下单 IP；设置 › 风控可以关闭风险分或自动暂停。

## 主题市场 · 应用收费 · 嵌入式应用

- **主题市场**（`ThemeListing`、开发者菜单「我的主题」、运营后台「主题审核」）：
  - 开发者在任意店铺的主题库导出 `.zip` 主题包，上传到「我的主题（开发者）」，填写介绍和 https 截图后提交审核。上传时只检查主题包，不会写入任何店铺。
  - 平台运营可以下载主题包检查，然后通过、拒绝（必须写原因）或下架。上传新版本后，已上架的主题会重新进入审核。
  - 商家在「在线商店 › 主题」的主题市场里一键添加：图片复制到自己的店铺，加入主题库但不发布，先自定义再发布。主题库最多 20 个主题的限制同样适用。
- **应用收费**（`App\Apps\AppBilling`，接口 `/api/v1/app_charges`，详见 `docs/api.md`）：
  - 应用用自己的令牌创建月费（每 30 天）或一次性收费（美元），把商家带到后台的确认页；商家批准或拒绝后回到应用的 `return_url`（必须在应用自己的域名下）。
  - 免费试用每个店铺每个应用只有一次；批准新的月费会取消旧的（换套餐）；卸载应用会取消月费；测试收费不扣钱。
  - 计费：计划任务 `lumee:bill-app-charges` 每天检查到期的月费，生成 `apps` 类型的平台账单（Stripe 订阅的店铺加到下一张 Stripe 发票）。平台保留 20%，开发者获得 80%，记录在 `app_charge_bills`，开发者页面显示近 30 天和累计收入。
  - 商家「应用」页显示每个应用的月费、试用到期和下次扣费日期，以及应用月费合计。
- **嵌入式应用（App Bridge）**：
  - 开发者勾选「嵌入后台打开」后，应用在后台页面里用 iframe 打开。地址带 60 秒有效的会话令牌（JWT，HS256，用应用签名密钥签名，`App\Apps\SessionToken`）。
  - 应用页面加载 `/app-bridge.js`，可以获取新的令牌、显示提示、设置标题、跳转后台页面。后台只接受来自应用地址同源的消息，并且只允许跳转到后台内的路径。
  - 应用市场卡片可以显示开发者填写的价格说明。

## 付费主题 · 开发者结算 · 客户隐私请求

- **付费主题**：开发者可以给主题设置一次性价格（US$29–349 的固定档位，或免费）。商家购买时需要确认价格，且店铺必须是付费套餐；费用计入平台账单（`themes` 类型，Stripe 订阅的店铺加到下一张 Stripe 发票）。每个店铺只买一次，之后重新添加免费。开发者获得 80%。
- **开发者结算**（`App\Billing\PartnerPayouts`，开发者菜单「收入与结算」，运营后台「开发者结算」）：
  - 应用收费和主题销售的开发者分成，只有商家付清对应平台账单后才计入可结算金额。
  - 计划任务 `lumee:partner-payouts` 每月 2 日把上个月可结算的金额合并成一笔结算；不足 US$25 顺延。也可以用 `--period=YYYY-MM` 手动运行。
  - 开发者填写 PayPal 邮箱或银行账户（加密保存，页面上只显示部分内容）。运营通过 PayPal 或银行转账付款后，填写流水号标记为已支付。
- **客户隐私请求（GDPR / CCPA）**（`App\Customers\Privacy`，客户 › 隐私请求）：
  - 顾客在账户页可以下载自己的数据（JSON：资料、订单、评论、订阅、询价、到货通知），也可以输入密码申请删除账户。
  - 商家在「隐私请求」里处理删除申请（页面显示 30 天的处理期限）。删除时：删掉客户账户，订单保留金额和商品但清除姓名、邮箱、地址、电话、备注和 IP（只留国家和省份），评论改为匿名，取消订阅，删除到货通知和营销邮件记录，并给顾客发确认邮件。顾客还有未付款或未发货的订单时不能删除。
  - 客户详情页可以直接导出或删除某位客户的数据（删除需要输入客户邮箱确认）。
  - 已安装的应用可以订阅 `customers/data_request` 和 `customers/redact` 两个 Webhook，同步导出或删除自己保存的数据。

## 智能分类 · 预售 · 数字商品 · 到店自提

- **智能分类**（`App\Catalog\SmartCollections`）：分类可以选择「按条件自动收录」，条件包括商品标签、类型、品牌（等于）、名称（包含）、价格（大于/小于）、库存（有货/缺货），可以要求满足全部或任一条件。
  - 成员写入普通的分类商品表，所以店铺分类页、按分类的折扣和自动折扣都照常生效。
  - 新建或修改商品、导入商品、库存从有货变缺货（或反过来）时自动更新；商品编辑页不能手动把商品移出智能分类。切换回手动分类时保留当前商品。
- **预售**（`App\Catalog\Preorders`）：商品可以开启「缺货时继续接受预订」，设置预计发货日期、说明和每个规格的预订上限。
  - 库存为 0 时商品页显示「预订」按钮和发货日期；库存会变成负数，表示待补货的数量。购物车和结账按上限检查。
  - 超出库存卖出的订单行标记为预售，订单页和后台都会显示。
- **数字商品**（`App\Catalog\DigitalDelivery`）：商品编辑页上传文件（每个商品最多 10 个，单个不超过 500MB，存在私有磁盘）。
  - 付款后自动生成下载链接（每个链接 5 次、30 天有效），通过邮件和订单页交付；后台可以重置下载次数。
  - 只买数字商品时，结账只有「数字交付」一个选项（不收运费），订单自动标记为已完成。
- **到店自提**（设置 › 运费）：最多 10 个自提点（名称、地址、营业时间、取货说明）。开启后结账页出现免运费的「到店自提」选项；订单页和后台订单详情显示自提点，商家在买家取货后点「发货」完成订单。

## 联盟营销 · 搭配推荐 · 编辑订单 · 自提通知

- **联盟营销**（`App\Marketing\Affiliates`，营销 › 联盟营销）：
  - 商家添加推广员（名称、邮箱、推广码、佣金比例）。访问带 `?ref=推广码` 的任何店铺页面会记下推广员（Cookie，默认 30 天，以最后一次点击为准），同一浏览器重复点击不重复计数。
  - 订单付款后按「折扣后的商品金额」（不含运费和税）计算佣金；推广员自己下单不算。部分退款按比例减少佣金，取消订单作废佣金。
  - 退货期（默认 30 天）过后才能结算：商家线下付款后在后台点「结算」。每个推广员有一个私密的统计页 `/affiliate/{token}`，可以看到点击、订单和佣金。
- **搭配推荐**（`App\Catalog\Upsells`）：
  - 商品页「经常一起购买」：商家可以在商品编辑页手动选最多 3 个；不选时根据近 180 天同一订单里的商品自动推荐（缓存 6 小时）。只有一个规格的商品可以勾选后一键加入购物车（`POST /cart/add-many`），其他商品链接到商品页选规格。
  - 购物车页「你可能还喜欢」：根据购物车里商品的搭配推荐，排除已经在购物车里的商品。
- **编辑订单**（`App\Orders\OrderEditor`，订单详情 › 更多 › 编辑订单）：
  - 未发货、未取消的订单可以修改数量、删除商品、添加商品；库存同步调整，税费重新计算，折扣金额保留（不超过新的小计）。
  - 已付款订单：金额变少时，差价通过正常退款流程原路退回（可选给买家发退款通知）；金额变多时记录「待补付」，商家收到后点「已收到补付」。订单的 `total` 始终是实际收到的金额。
  - 未付款订单只有银行转账、账期付款可以编辑（在线付款链接的金额已经固定）。数字商品已交付的订单不能编辑。每次修改记录在订单动态里，并触发新的 Webhook `orders/updated`。
- **自提通知**：到店自提的订单点「发货」时，发送「可以取货了」邮件（带自提地址、营业时间和取货说明），而不是发货通知。可以在「设置 › 邮件通知」里预览和关闭。

## 运费与收款

- **运费区域**（设置 → 运费）：每个区域包含若干国家，买家按收货国家匹配到对应区域。
  - 没被任何区域包含的国家，使用「其他国家」区域（即不选国家的区域）。没有这个区域的话，这些国家不能下单。
  - 一个国家只能属于一个区域，「其他国家」区域最多一个。
  - 每条运费可以按订单金额设置上下限（按折扣后金额计算，例如满 99 包邮），也可以按重量设置上下限。下限包含在内，上限不包含。
  - 商品的每个 SKU 可以填写重量（克）。CSV 导入导出中对应的列是 `Variant Grams`。
  - 结账页切换国家时，运费选项会实时刷新。
- **收款设置**（设置 → 收款）：
  - Stripe、PayPal、Airwallex（这三种都需要平台配置密钥）、线下付款、测试支付，每种方式都可以单独开关；至少要保留一种。
  - 线下付款可以自定义名称（例如 Wise transfer、Cash on delivery），付款说明必须填写。说明会显示在结账页、订单状态页和订单确认邮件里。
- **Stripe Connect：商家收款到自己的账户**（`App\Payments\StripeConnect`）：
  - 开启方式：在 `.env` 里设置 `STRIPE_CONNECT=true`，并填写 `STRIPE_CONNECT_WEBHOOK_SECRET`。
    - 在 Stripe 后台添加一个 Connect 类型的 webhook 端点（Events on connected accounts），地址同样是 `/webhooks/stripe`，订阅 `account.updated` 和 `account.application.deauthorized`。
    - 平台原有的 webhook 端点继续订阅 `checkout.session.completed` 和订阅相关事件，另外加上 `charge.dispute.created`、`charge.dispute.updated`、`charge.dispute.closed`（拒付处理）。
    - 不开启时，所有信用卡付款仍然进入平台账户，方便本地开发。
  - 商家开通流程（设置 → 收款 → 收款账户）：
    1. 商家选择公司或个人所在的国家/地区（限 Stripe 支持的国家，中国大陆不在其中，页面上有提示），点击「连接 Stripe 账户」。
    2. 系统为店铺创建一个 Express 账户（每家店只创建一次），然后跳转到 Stripe 托管的开户页面，填写公司资料和银行卡。
    3. 填完后回到后台，系统自动刷新账户状态。之后状态变化由 `account.updated` webhook 同步。
  - 账户状态：未连接、资料未完成、审核中、需要补充资料、已开通。只有已开通收款的店铺，结账页才显示信用卡付款。如果信用卡是唯一开启的付款方式但账户还不能收款，保存设置时会提示错误。
  - 付款方式：destination charge。钱进入商家的账户（`on_behalf_of` 为商家账户，买家账单上显示的商户也是商家）；平台佣金按套餐费率作为 `application_fee_amount` 当场扣除，试用期不扣。
  - 订单会记录收款账户（`orders.stripe_account`）和扣除的佣金（`orders.application_fee`）。
  - 退款：带 `reverse_transfer` 和 `refund_application_fee`，钱从商家账户扣回，平台佣金按比例退回。
  - 拒付（`App\Payments\StripeDisputes`，处理平台 webhook 的 `charge.dispute.*` 事件）：
    - 按 PaymentIntent 找到订单，把拒付金额、原因和提交证据截止时间记在订单上（`orders.dispute`）。后台订单页会显示提醒，同时给店主发邮件。
    - Connect 订单在拒付开始时，自动从商家账户冲回这笔转账（transfer reversal），所以拒付由商家承担，而不是平台。
    - 商家胜诉时，冲回的钱会自动转回商家账户。
    - 证据由平台在 Stripe 后台提交，商家回复邮件提供发货凭证。
    - 同一个 webhook 重复送达时，不会重复冲回；没有用 Connect 的订单只做记录。
  - 商家还可以打开 Stripe 后台查看余额和打款记录（一次性登录链接），也可以断开账户。断开后买家不能再用信用卡付款；已有订单的退款仍从原账户退回。
- **Stripe 的其他付款方式**：在 Stripe 卡片里可以勾选 Klarna、Afterpay / Clearpay、iDEAL、Bancontact、Alipay、WeChat Pay。
  - 只有支持店铺结算货币的方式才能勾选，也只有这些方式会传给 Stripe，比如 iDEAL 只支持欧元。
  - 结账页的付款方式名称会显示为「Card, Klarna, …」。
  - 这些方式还需要在 Stripe 后台的「Payment methods」里开启。如果 Stripe 因为某个方式没有开启而拒绝创建付款页，系统会去掉指定的方式再创建一次（使用 Stripe 后台默认的付款方式），买家照样可以付款，同时记录错误。
- **Airwallex 空中云汇**（`App\Payments\AirwallexGateway`）：
  - 配置：在 `.env` 里填写 `AIRWALLEX_CLIENT_ID`、`AIRWALLEX_API_KEY`、`AIRWALLEX_ENV`（`demo` 或 `prod`）和 `AIRWALLEX_WEBHOOK_SECRET`。webhook 地址是 `/webhooks/airwallex`，订阅 `payment_intent.succeeded`。
  - 付款流程：
    1. 下单时创建 PaymentIntent（订单令牌作为幂等 ID，带商品明细）。
    2. 买家先到 `/checkout/airwallex/{订单令牌}`，这个页面用 Airwallex 官方 JS 转到它的托管付款页，卡号不经过店铺。
    3. 付款后回到 `/checkout/airwallex/return`，系统查询 PaymentIntent：状态为 SUCCEEDED、金额和币种都一致，才标记为已付款。
  - Webhook 签名是 `HMAC-SHA256(x-timestamp + 请求体)`，超过 10 分钟的请求会被拒绝；用订单号伪造的通知会被忽略。
  - 退款通过 Airwallex 原路退回。
- **PayPal**（Orders v2 接口，`App\Payments\PayPalGateway`）：
  - 配置：在 `.env` 里填写 `PAYPAL_CLIENT_ID`、`PAYPAL_SECRET`、`PAYPAL_MODE`（`sandbox` 或 `live`）和 `PAYPAL_WEBHOOK_ID`。
  - 付款流程：
    1. 买家选择 PayPal 后跳转到 PayPal 确认付款。
    2. 确认后回到 `/checkout/paypal/return`，系统立即扣款（capture）。
    3. 核对金额和币种一致后，订单标记为已付款。
    4. 发给 PayPal 的订单带有商品明细；运费、税、折扣分项列出。
  - Webhook：地址是 `/webhooks/paypal`，需要订阅 `CHECKOUT.ORDER.APPROVED` 和 `PAYMENT.CAPTURE.COMPLETED`。
    - 买家确认后直接关掉页面、没有回到店铺时，靠 webhook 补扣款。
    - webhook 签名通过 PayPal 的接口验证；用订单号伪造的通知会被忽略。
  - 退款：在后台退款时原路退回（按 capture 退款，带幂等键）。PayPal 返回失败时，订单不做任何改动。
  - 币种限制：PayPal 不支持 AED，CNY 只有中国大陆的账户能用。店铺货币不受支持时，结账页不显示 PayPal，收款设置页会给出提示。
  - 订单的 `payment_reference` 在付款前存 PayPal 订单号，付款后存 capture id。
- **税费**（设置 → 税费）：
  - 计税方式：
    - 价格含税：欧盟、英国、澳洲等地的常见做法。订单总价不变，结账页显示「Including VAT 20%」。
    - 结账时另外加税：美、加的常见做法。税额加在总价上。
    - 可以选择运费是否也收税。
  - 税率：
    - 按收货国家设置；同一国家可以再按州或省代码设置（例如 US + CA），州或省的税率优先。
    - 内置常用税率：欧盟 27 国标准 VAT、英国、澳洲、新西兰、加拿大 GST、瑞士、挪威、日本、新加坡。
    - 没有设置税率的国家不收税。
  - 商品可以单独设为「不收税」（例如礼品卡）。有折扣时，折扣按金额比例分摊到收税商品和不收税商品上。
  - 结账页切换国家或州时，税额实时刷新。
  - 订单会保存税额、计税方式和税名，在订单页、确认邮件、后台订单详情和 Stripe 付款页里显示。

## 顾客账户（店铺前台）

- 前台页头有账户图标，入口是 `/account/login` 和 `/account/register`。
- 账户页可以查看订单记录、保存默认地址、修改资料、修改密码。登录后结账时会自动填好邮箱和地址。
- **安全设计**：
  - 游客下单时就会生成客户记录。为防止有人用别人的邮箱注册后看到对方的订单，**邮箱验证通过之前不显示任何订单**。注册后系统会发送验证邮件。
  - 游客买家可以通过「忘记密码」给自己设置密码。重置链接只发到这个邮箱，所以重置成功也算验证了邮箱。
  - 每个店铺的账户互相独立：同一个邮箱在两家店是两个账户，一家店的会话和链接在另一家店无效。
  - 链接中的 token 只存哈希值，只能用一次（验证链接 3 天有效，重置链接 1 小时有效）。
  - 登录、注册、发邮件都有频率限制。「忘记密码」不会透露某个邮箱是否注册过。登录后的跳转只允许站内路径。
- 后台「客户」列表显示账户状态（游客 / 待验证邮箱 / 已注册）和是否订阅营销邮件，并支持搜索和分页。

## 页面 · SEO · 搜索

- **页面**（在线商店 → 页面）：
  - 用来写关于我们、常见问题、配送政策、退换货政策、隐私政策、服务条款等。
  - 每种页面都有一键创建的英文模板。用模板创建的页面默认「未发布」，模板内容不构成法律意见。
  - 正文用 Markdown 编写，可以预览。渲染时会去掉原始 HTML 和不安全的链接。
  - 页面可以在「导航菜单」中添加到页头或页脚（新增链接类型：某个页面、搜索）。
- **SEO**：
  - 商品、分类、页面、首页都可以自定义搜索结果中的标题和描述，后台显示 Google 搜索结果预览。
  - 店铺页面自带 canonical、Open Graph 和 Twitter Card 标签，商品页还有 schema.org Product 结构化数据（价格、库存、品牌）。
  - 每个店铺有自己的 `/sitemap.xml` 和 `/robots.txt`。robots.txt 会禁止抓取购物车、结账、账户等页面。
- **搜索**：页头的搜索图标进入 `/search`。搜索匹配标题、品牌、类型、标签、描述和 SKU，只返回在售商品，搜索页不被搜索引擎收录。
- 商品编辑页新增「品牌」和「标签」字段。

## 多币种显示

- 在设置 → 多币种中开启，选择买家可以切换的货币。买家在页脚切换货币，商品价格按汇率换算显示。
- **只换算显示的价格**：购物车、结账、订单、付款始终使用店铺货币。购物车和结账页会写明「将按 USD 扣款」以及实际金额，避免买家误解。
- 汇率每天由 `lumee:exchange-rates` 自动更新，也可以手动点「立即更新」。更新失败时继续使用上次的汇率。商家可以为某个货币填写自定义汇率，代替每日汇率。
- 换算后的价格可以选择取整方式：.99（推荐）、整数、不取整。
- 首次访问时，可以按买家国家自动选择货币。这需要店铺接入 Cloudflare 等 CDN，由 CDN 提供 `CF-IPCountry` 头。

## 商品批量导入 / 导出

后台「商品」页右上角有 **导入** 和 **导出** 两个按钮，需要「商品」权限。

- **文件格式**：CSV，与 Shopify 导出的商品 CSV 兼容（可直接导入），也支持中文表头（标题、价格、库存、规格1名称……）。
  - Excel 在中文 Windows 上另存的 GBK 文件会自动转成 UTF-8。
  - 限制：文件不超过 5MB；一次最多 1000 个商品、10000 行。
  - 导入弹窗里可以下载模板。
- **同一商品占多行**：Handle 相同的行属于同一个商品，第一行填写商品信息，后面的行只填规格值、SKU、价格、库存和图片。
  - 没有 Handle 列时，由标题生成网址；中文标题会生成 `product-xxxxxxxx` 形式的网址。
  - 规格名写 `Title`、值写 `Default Title`，表示商品没有规格（Shopify 的写法）。
- **两步导入**：
  1. 上传后先预览。预览会给出商品数、SKU 数、新商品和已存在的商品，以及每一行的问题（价格无效、规格组合重复、缺少规格值等）。这一步不会修改商品库。
  2. 确认后由队列任务 `RunProductImport` 在后台导入，弹窗显示进度。需要运行 `php artisan queue:work`。
- **已存在的商品**（按 Handle 判断）有两种处理方式：
  - 跳过（默认）；
  - 用文件内容覆盖：同一规格组合的 SKU 保持原有 ID，已有订单和购物车不受影响。
- **分类**：「Collection」列按名称匹配已有分类，不存在的分类会自动创建。
- **图片**：「Image Src」中的链接由后台下载到店铺媒体库。为防止 SSRF：
  - 只允许 http/https 和 80/443 端口；
  - 域名必须解析到公网 IP，内网、回环和云元数据地址一律拒绝，连接直接使用校验过的 IP；
  - 不跟随跳转，单张图片不超过 10MB，只接受 jpg、png、webp、gif。
  - 某张图片下载失败不会影响商品本身，失败的图片会列在导入结果里。
- **导出**：按同样的格式导出全部商品（带 BOM，Excel 可直接打开中文）。导出的文件可以修改后重新导入。

## 员工账号与权限

- **角色**：**所有者**拥有全部权限；**员工**只能使用被授权的模块。可授权的模块有：订单、商品与分类、客户、营销、数据分析、在线商店、店铺设置（定义见 `App\Tenancy\Permissions`）。
- **只有所有者能管理员工**（后台「设置 → 员工」）：邀请、修改权限、移除、重发或取消邀请。所有者本人不能被修改或移除。
- **权限由后端强制执行**：
  - 每个接口都由 `perm:` 中间件检查权限（见 `routes/api.php`）；后台菜单和页面只是相应地隐藏，并不依赖前端来防护。
  - 首页接口也只返回该员工有权看到的数据。
  - 员工的成员资格在每次请求时都会重新检查，所以移除员工后立即生效。
- **邀请流程**：
  1. 所有者填写员工邮箱并勾选权限，系统通过队列发送邀请邮件，链接 7 天内有效。
  2. 员工打开链接：新用户设置名字和密码即可加入；已有 Lumée 账号的用户需要输入原密码，加入后可以在多家店铺之间切换（侧边栏顶部的店铺名可以点击切换）。
  - **安全**：数据库只保存邀请令牌的 SHA-256 哈希；链接只能使用一次；重新发送后旧链接立即失效；接受邀请时必须使用被邀请的那个邮箱。

## 营销 · 设置 · 数据分析

- **折扣码**（后台「营销」）：支持百分比、固定金额、免运费三种，可设置最低消费、总使用次数、每位买家限用一次和有效期。
  - **使用方式**：买家在购物车中输入折扣码，结账时会再校验一次；校验时锁住折扣码记录，同时下单也不会超出使用次数。
  - **包邮门槛**：「满额包邮」按**折扣后**的金额计算。
  - **Stripe**：Stripe 不支持负数的行项目，所以带折扣的订单会合并成一行、按实付总额收款。
- **自动折扣**（后台「折扣 → 自动折扣」，`App\Promotions\Promotions`）：不需要折扣码，满足条件就自动生效。三种活动都可以设置开始和结束时间、启用或停用。
  - **限时折扣**：
    - 可以对全部商品、指定分类或指定商品打折（百分比，或每件减固定金额）。
    - 直接降低店铺前台的商品价格，原价显示为划线价，商品页显示「Save x%」和活动名称，可选倒计时。
    - 购物车、结账、订单、Google 商品数据源、追踪事件都使用折后价。
    - 实现方式：店铺前台的请求里，`ProductVariant` 读取 `price` 时返回折后价，所以后台、库存和导入导出仍然是原价。
    - 同一商品有多个活动时，取最低价。
  - **满减**：最多 5 档，例如「满 100 减 10、满 200 减 30」，也可以按百分比打折。
    - 按限时折扣后的商品金额计算，自动使用达到的最高一档。
    - 购物车会提示「再买 $X 可省 $Y」，并显示进度条。
  - **捆绑优惠**：选 2–10 件商品，购物车里每件至少有 1 件时算作一套，每套减固定金额或打折；买两套就优惠两次，同一商品的任何款式都算。
  - **和折扣码一起用**：
    - 满减和捆绑优惠之间可以叠加。
    - 活动允许叠加时，折扣码按扣掉活动优惠后的金额计算。
    - 不允许叠加时，自动使用对买家更划算的一种，购物车会说明原因；没有用上的折扣码不计入使用次数。
    - 免运费折扣码总可以叠加。
  - **订单记录**：订单保存每一项优惠（`orders.discount_lines`：活动或折扣码、名称、金额），在订单页、确认邮件和后台订单详情里分行显示；`discount_total` 是所有优惠的合计。
  - **统计**：满减和捆绑优惠记录参与的订单数和优惠总额，显示在活动列表里。
  - **其他计算**：包邮门槛和税费都按扣除所有优惠后的金额计算。
- **店铺信息**（后台「设置 → 店铺信息」）：可以修改店铺名称、结算货币和时区。更换货币不会换算已有价格，只会更换货币单位。
- **自定义域名**（后台「设置 → 域名」）：添加域名 → 设置 CNAME 解析到 `LUMEE_CNAME_TARGET`（根域名则设置 A 记录指向 `LUMEE_SERVER_IP`）→ 点击验证 → 可设为主域名。
  - **未验证不生效**：域名验证通过之前不会显示店铺，所以别人无法抢占不属于自己的域名。
  - **本地开发**：以 `.localhost` 或 `.test` 结尾的域名会直接通过验证。
  - **HTTPS**：用 Caddy 的 on-demand TLS 自动签发和续期证书。Caddy 签发证书前会请求 `/internal/tls/ask`，只有已验证、并且套餐包含自有域名的店铺域名才能拿到证书。部署方式见 [docs/https.md](docs/https.md) 和 [deploy/Caddyfile](deploy/Caddyfile)。
- **数据分析**（后台「数据分析」）：
  - 可查看近 7、30、90 天的销售额（只算已付款订单）、订单数、客单价和新客户数，并与上一个相同长度的周期对比。
  - 包含每日销售额图表（可切换为表格）、热销商品和销售地区。
  - 日期按店铺所在时区计算。
- **邮件营销**（后台「营销」，`App\Marketing\CampaignSender`）：
  - 订阅来源：
    - 结账页的「Email me with news and offers」勾选框。
    - 首页可以添加的「邮件订阅」区块。
    - 订阅弹窗（可以设置延迟几秒弹出，可以附带折扣码；每位访客只弹一次，结账页不弹）。
    - 顾客账户页。
  - 只有同意接收营销邮件（`accepts_marketing`）的顾客才会收到，客户记录里会保存订阅来源和时间。
  - 写邮件：
    - 收件人可选：全部订阅者、下过单的订阅者、还没下过单的订阅者。
    - 内容包括主题、预览文字、大标题、Markdown 正文、按钮，以及最多 4 件推荐商品（显示限时折扣价）。
    - 编辑时右侧实时预览，可以先发一封测试邮件给自己。
  - 发送：
    - 可以立即发送，也可以定时发送（`lumee:send-campaigns` 每分钟检查一次）。
    - 发送时先把收件人名单固定下来，再按每批 100 封交给队列发送；只发送状态为「排队中」的收件人，所以失败重试不会重复发。
    - 发送前又退订的人会被跳过。
    - 已发送的邮件不能再修改。
  - 统计：送达、打开率（追踪像素）、点击率（链接经过 `/email/click`，带签名，不能被用来跳转到其他网站）、退订人数。
  - 退订：
    - 每封邮件都有退订链接，并带 `List-Unsubscribe` 和 `List-Unsubscribe-Post` 邮件头（Gmail、Yahoo 会显示一键退订按钮）。
    - 打开退订链接只显示确认页，点按钮才会退订，避免邮件安全扫描器误点。
    - 店铺暂停营业时，退订链接仍然可以用。
- **自动化邮件**（后台「营销 → 自动化」，`App\Marketing\Flows`，`lumee:run-flows` 每 10 分钟运行）：
  - 三个流程，第一次打开页面时自动创建（默认关闭，内置英文模板，可以直接修改后开启）：
    - **欢迎邮件**：有人订阅时触发；可选「顾客下单后不再发送后面的欢迎邮件」。
    - **购后关怀**：顾客第一笔订单付款后触发，每位顾客只收到一次。
    - **老客召回**：顾客最后一次下单超过 30、60、90 或 180 天时触发；每次流失只发一次，再次下单后停止。
  - 每个流程最多 5 封邮件。每封可以设置等待时间（触发后或上一封之后，按小时或天）、主题、正文、按钮、推荐商品和折扣码，也可以预览或发测试邮件。
  - 实现：每封邮件就是一条 `email_campaigns` 记录（`email_flow_id`、`flow_position`、`delay_hours`），和群发邮件共用模板、打开和点击统计、退订链接；`email_flow_enrollments` 记录每位顾客走到第几封。
  - 停止条件：顾客退订、流程被关闭、按设置下单后停止。先锁定当前步骤再发送，所以重叠运行时也不会重复发送。
- **营销邮件额度**：
  - 群发和自动化邮件共用每月额度：试用 500、入门版 2,000、基础版 10,000、专业版 50,000 封，在 `config/plans.php` 的 `marketing_emails` 里修改。
  - 订单相关邮件不计入额度。
  - 群发时如果收件人超过剩余额度，会直接提示升级或缩小范围。定时群发到时间时如果超额，会退回草稿。
  - 自动化邮件超额后，会顺延到下个月额度重置后再发。
  - 自动化页面会显示本月已用 / 总额度。
- **弃单挽回**（后台「订单 → 弃单」）：
  - 买家进入结账页并填写邮箱后（页面会在后台把邮箱发给服务器，已登录的顾客自动带入），就记录为一个弃单。
  - 超过设定时间（1、4、10 或 24 小时，从最后一次操作购物车算起）仍未付款，`lumee:recover-checkouts`（每 15 分钟检查一次）就发一封提醒邮件：
    - 用买家结账时的语言，带商品图片和小计，可选附带折扣码。
    - 邮件里的按钮会在任何设备上恢复原来的购物车，并直接进入结账页。
  - 不发送的情况：每个弃单只发一封；已经下单的买家、超过 7 天的弃单、店铺暂停营业时都不发送。
  - 通过提醒邮件完成的订单会标记 `orders.recovered`。页面显示近 30 天发送了多少封、挽回了多少订单和销售额。
- **追踪代码与 Google 购物**（后台「营销 → 追踪代码」）：
  - 支持三种代码：Google Analytics 4、Meta Pixel、TikTok Pixel。ID 按格式严格校验后才会输出到页面上，统一由 `storefront/tracking.blade.php` 加载。
  - 自动上报的事件：
    - 浏览商品：GA4 `view_item`，Meta 和 TikTok `ViewContent`。
    - 加入购物车：GA4 `add_to_cart`，Meta 和 TikTok `AddToCart`。
    - 开始结账：GA4 `begin_checkout`，Meta 和 TikTok `InitiateCheckout`。
    - 完成购买：GA4 `purchase`，Meta `Purchase`，TikTok `CompletePayment`。同一个订单在同一浏览器只上报一次，并带有事件 ID，方便以后接入服务器端事件时去重。
  - 可选 Cookie 同意提示：开启后，买家同意之前不加载任何追踪代码；拒绝后也不加载。
  - Google Merchant Center 商品数据源：
    - 地址是 `/feeds/google.xml`，其他语言加前缀，如 `/fr/feeds/google.xml`。
    - 每个款式一条，包含原价和促销价、库存、图片、品牌、款式分组。
    - 后台可以复制每种语言的数据源地址。
- **商品评论**（后台「商品 → 评论」）：
  - 买家在商品页写评论：1–5 星、标题、内容，最多 3 张图片。
  - 评论邮箱有过已付款的这个商品订单时，显示「已购买」标记。
  - 自动发布方式可选：只发布已购买买家的（默认）、全部发布、全部人工审核。
  - 商品页显示平均分、星级分布和分页列表，商家回复会显示在评论下方，结构化数据会输出 `aggregateRating`，搜索结果可以显示星级。
  - 后台可以筛选（状态、星级、关键词）、发布或隐藏、回复、删除（同时删除图片），也可以批量操作。
  - CSV 导入：适合从其他平台迁移，必填列是 `product_handle`、`rating`、`author`、`body`。
  - 防垃圾评论：表单里有隐藏的陷阱字段，每个 IP 每分钟最多提交 5 次。
  - **邀请评价邮件**（`App\Reviews\ReviewRequests`，`lumee:review-requests` 每小时运行）：
    - 订单发货后过一段时间（3、7、14 或 30 天，默认 7 天，在「评论设置」里修改），用买家下单时的语言发一封邮件，列出买到的商品。
    - 每个商品带一个「Write a review」按钮，点开后直接展开评论表单，并填好买家的名字和邮箱；链接带订单令牌，只对订单里的商品有效。
    - 每个订单只发一次；买家已经评价过所有商品、订单已退款或取消、发货超过 60 天、店铺关闭了评论功能时都不发送。
    - 和其他订单邮件一样，可以在「设置 → 邮件通知」里预览、发测试邮件或关闭。
  - 评论邮箱不会公开，名字显示为「名 + 姓的首字母」。
- **博客**（后台「在线商店 → 博客」）：
  - 文章用 Markdown 编写，和页面使用同一个安全渲染器。可以设置封面图、作者、标签、摘要和 SEO。
  - 文章可以定时发布：发布时间在未来的文章，到时间后才会出现。
  - 店铺前台：
    - 列表页 `/blog`，可按标签筛选。
    - 文章页 `/blog/{handle}`，带 `BlogPosting` 结构化数据和相关文章。
    - Atom 订阅 `/blog/feed.xml`。
    - 文章会自动加入 sitemap。
  - 导航菜单可以添加「博客」链接；文章可以在「翻译」里翻译成其他语言。
- **接口限流**：每个需要限流的操作都有自己独立的计数器（见 `AppServiceProvider::RATE_LIMITS`），互不影响。

## 平台视觉风格

- **整体风格**：商家后台、登录页和平台首页统一使用**绿白风格**——以白色为主，绿色 `#0E8A5F` 只用在按钮、链接和选中状态上。
- **设计 Token**：定义在 `packages/ui-tokens/tokens.css`（并复制一份到 `backend/public/css/platform-tokens.css`）。新增后台页面时，统一使用 `--brand-*`、`--bg`、`--surface`、`--border` 这些变量。
- **平台标志**：使用 `brand/platform-mark.svg`。原来的蝴蝶 Logo 仍保存在 `brand/` 目录中。
- **店铺主题**：Aurora 等主题有自己独立的样式（`backend/public/css/lumee-tokens.css`），颜色由商家在「店铺装修」里自行设置，不受平台风格影响。

## 商品分类与导航菜单

- **商品分类**（后台「商品 → 商品分类」）：
  - **组织商品**：可以手动把商品加入分类并拖动排序，也可以选择按最新、价格或名称自动排序。
  - **在商品页设置**：也可以在商品编辑页的「所属分类」里直接选择分类。
- **店铺页面**：
  - `/collections`：全部分类。
  - `/collections/{handle}`：某个分类，买家可以切换排序方式，支持分页。
  - `/collections/all`：全部商品。
- **导航菜单**（后台「在线商店 → 导航菜单」）：有主菜单和页脚菜单两个。
  - **链接类型**：菜单项可以链接到首页、全部商品、全部分类、某个分类、某个商品或自定义网址。
  - **下拉菜单**：主菜单支持一级下拉；在手机上显示为侧滑菜单。
  - **链接不会失效**：菜单按分类或商品的 ID 保存，修改分类网址后链接依然有效；分类或商品被删除、隐藏后，店铺里会自动不再显示这个链接，后台会标出失效的菜单项。
  - **链接安全**：自定义网址只允许 `/`、`#`、`http(s)://` 和 `mailto:` 开头的地址。
- **店铺装修**：「精选商品」模块可以选择从某个分类取商品；新增「分类展示」模块，用来在首页展示分类入口。

## 邮件通知

| 邮件 | 收件人 | 什么时候发 |
|---|---|---|
| 订单确认 | 买家 | 银行转账：下单时（邮件里附付款说明）；银行卡：付款成功时 |
| 收款确认 | 买家 | 银行转账订单被商家标记为已付款时 |
| 发货通知 | 买家 | 商家点击发货时（邮件里附物流单号和 17track 查询链接） |
| 新订单提醒 | 商家 | 与订单确认同时发出（中文） |

- **发件方式**：所有店铺都从平台地址 `MAIL_FROM_ADDRESS` 发信，这样 SPF/DKIM 验证能通过、邮件不容易进垃圾箱。买家看到的发件人名称是店铺名，直接回复会发到商家设置的邮箱。
- **商家设置**：在后台「设置 → 邮件通知」里可以修改发件人名称、回复邮箱和新订单提醒的收件邮箱，单独开关每一类邮件，也可以预览邮件或给自己发一封测试邮件。
- **发送记录**：订单详情页的「邮件记录」显示每封邮件的状态（排队中 / 已发送 / 发送失败）。买家说没收到时，可以点「重新发送」，即使这类邮件被关闭了也会发出。
- **品牌样式**：邮件自动使用店铺已发布主题的 Logo 和主色。邮件模板在 `resources/views/emails/`。
- **队列**：邮件放在后台队列里异步发送，所以**需要一直运行队列进程**，否则邮件会一直处于「排队中」：
  ```bash
  cd backend
  php artisan queue:work
  ```
  发送失败时会自动重试 3 次（间隔 30 秒、2 分钟、10 分钟），三次都失败才记为发送失败。
- **本地开发**：`.env` 中 `MAIL_MAILER=log`，邮件不会真的发出去，而是写入 `storage/logs/laravel.log`。
- **上线前**：把 `MAIL_MAILER` 改成 `smtp`（也可以用 Resend、SES、Postmark 等服务），填好对应账号，并为发信域名配置 SPF、DKIM 和 DMARC 记录。

## 店铺主题

| 主题 | 风格 |
|---|---|
| **Aurora** | 轻奢珠宝风：玫瑰金、象牙白、衬线字体 |
| **Fresh** | 清爽绿白风：白色为主、绿色点缀、无衬线字体，适合各类商品 |

- **默认主题**：新开的店铺默认使用 **Fresh**，可以在 `.env` 中通过 `LUMEE_DEFAULT_THEME` 修改。已有店铺保持自己原来的主题，不受影响。
- **切换主题**：在「在线商店 › 主题」的主题库里，给任一主题点「发布」，店铺就会换成它。每个主题的设置单独保存，换回去时之前的设置都还在。
- **主题继承**：Fresh 在 `config/themes.php` 中声明 `extends => aurora`，没有提供的模板会自动使用 Aurora 的。Fresh 自己只有 `themes/fresh/layout.blade.php` 和 `checkout-layout.blade.php` 两个文件，用来调整样式。查找模板由 `ThemeContext::view()` 负责。
  - **新增主题的方法**：在 `config/themes.php` 里加一项配置，再新建 `resources/views/themes/{主题}/layout.blade.php`，把样式写进 `@push('theme-overrides')`——这个区块在页面自身的样式之后输出，所以能覆盖它们。
- **预览令牌**：令牌里包含要预览的主题（模板名，或主题库里某个主题的 `r{id}`），并且整体签名，所以不能把令牌改成预览别的主题或别的店铺的主题。

## 各市场的店铺装修

代码在 `backend/app/Themes/MarketThemes.php`，数据在 `store_theme_markets`（每个主题 × 市场一行，有草稿和线上两份）。

- **入口**：主题编辑器顶部的站点下拉框（「主站点」或某个市场），也可以从「设置 › 市场 › 本地化 › 店铺装修」进入。
- **只保存改过的内容**：编辑器始终编辑一份完整的配置；在某个市场里保存时，服务器和主站点对比，只记下不一样的设置和模块字段。没改过的内容一直跟随主站点，主站点以后的修改也会同步过来。
  - 改过的字段左侧有绿色竖线，标着「本市场」，点「恢复主站点」就改回主站点的值（这个字段重新跟随主站点）。
  - 改成和主站点一样的值，也等于恢复跟随。
- **首页的两种方式**：
  - 跟随主站点（默认）：可以改模块里的文字和图片、隐藏模块，不能增删和调整顺序。
  - 本市场自己的首页：点「改成本市场自己的首页」后可以随意增删、排序；主站点首页的改动不再影响它。随时可以「恢复跟随主站点」。
- **草稿和发布**：每个市场单独保存草稿、单独发布（按钮显示「发布到 某市场」），预览在这个市场的网址下（例如 `/es-mx/?_preview=…`）显示草稿。发布市场装修不会切换店铺主题。
- **翻译**：市场自己填写的文字（已经是当地语言）不会被主站点的主题翻译替换；跟随主站点的文字仍然使用翻译。
- **历史版本**：主站点和每个市场每次发布都保存一个版本（`theme_versions`，各保留最近 30 个），在编辑器的「历史版本」里可以恢复到草稿，确认后再发布。
- **安全**：市场里保存的内容同样经过 `ThemeService::sanitize` 校验，不合法的值（例如颜色或链接）会被丢弃，不会成为市场的覆盖。

## 模块、页面模板和活动页

模块定义在 `backend/config/theme_blocks.php`（所有主题共用），每个模块的模板在 `resources/views/themes/aurora/sections/`，数据由 `App\Themes\SectionData` 按当前市场查询。

- **新模块**：轮播横幅（每张可以单独设置手机图）、圆形分类入口、限时抢购（倒计时，时间到了自动隐藏；不填结束时间就用正在进行的自动折扣）、优惠券条（只显示能用的折扣码，点一下复制）、标签页商品、本市场热卖（按这个市场最近的销量）、跑马灯、当地信任条（按市场自动显示免邮门槛、支付方式、关税）、买家秀墙（评价里的带图晒单）、场景图热点、预计送达。
- **手机端**：每个模块都有「显示在：电脑和手机 / 只在电脑上 / 只在手机上」；商品列表类模块可以分别设置电脑和手机每行几个。
- **页面模板**：除了首页，商品页、分类页、购物车也由模块组成（`config.templates`）。每个模板有一个固定模块（商品信息、商品列表、购物袋），不能删除或隐藏，其他模块可以随意添加和排序；每种模块只能放在允许的页面（`on`）。
- **活动页**：「在线商店 › 页面」里把页面类型选成「活动页（用模块装修）」，保存后点「去装修这个页面」。活动页的模块存在主题配置里（`config.pages.{页面 id}`），所以和首页一样有草稿、发布、历史版本，每个市场也可以单独修改。网址仍是 `/pages/{handle}`；还没装修时显示默认模块。
- **版式风格**（主题设置 › 版式风格）：圆角、按钮形状、商品卡片样式、商品图片比例、模块间距，在主题自己的样式之后输出（`ThemeContext::styleCss()`）。
- **风格包**：主题设置里一键套用地区风格（美国大图简洁、欧洲极简可信、拉美热闹促销、东南亚高密度移动端、中东深色金调），设置字体、背景、点缀色和版式，保留品牌主色；在某个市场里套用，就只改这个市场。
- **编辑器**：左上角「正在装修」切换首页、商品页、分类页、购物车和各个活动页，预览同时切换到对应页面；添加模块时只列出这个页面能用的模块。在市场里，商品页等页面的结构跟随主站点，只能改文字、图片和隐藏模块。
- **翻译**：商品页、分类页、购物车和活动页模块里的文字，和首页一样出现在「在线商店 › 翻译 › 主题」里。

## 自动装修 · 装修检查 · 活动排期

代码在 `backend/app/Themes/`（AutoDesigner、DesignCopy、BannerComposer、DesignCheck、ThemeSchedules）。

- **自动装修**（编辑器工具栏的 ✨，或「设置 › 市场 › 本地化 › 店铺装修 › 自动装修这个市场」）：
  - 按市场的区域预设判断地区，没有预设时按国家判断（北美、欧洲、拉美、东南亚、中东），套用对应的风格包，保留品牌主色。
  - 首页按地区的模块顺序生成；没有数据的模块会跳过，例如没有打折商品就不放限时抢购，晒单少于 3 张就不放买家秀墙。
  - 文案用市场的语言写（`DesignCopy`，八种语言是逐条写的，不是机器翻译）。数字都取自设置：免邮门槛按运费设置换算成市场货币，退货天数来自退货设置，分期期数、货到付款、关税说明来自市场设置。金额按当地格式显示，例如墨西哥 `$980.00`、巴西 `R$ 245,00`。
  - 公告栏和购买保障也会换成当地语言的卖点。
  - 接下来进入准备期的购物节点，会用在首屏文案上（例如墨西哥 11 月下旬是「Regalos de Navidad」）。
  - 有商品图时，会用热卖商品的图片按品牌色合成首屏横幅（GD，电脑和手机各一张）。
  - 生成结果只放进草稿；在市场里生成时，首页会变成这个市场自己的首页。
- **装修检查**（工具栏的 ✓，发布时也会自动运行）：
  - 文案里的免邮门槛、退货天数和设置不一致：错误。
  - 文字还不是市场的语言：提醒。
  - 文字和背景对比度低于 4.5:1：错误；按钮文字对比度不足：提醒。
  - 手机前两屏看不到商品：东南亚、拉美为提醒，其他地区为建议。
  - 首屏图片超过 300 KB：提醒。
  - 欧洲市场没有写明含税：提醒。
  - 链接或热点指向这个市场买不到的商品：错误。
  - 优惠券码不能用：提醒；限时抢购不会显示：建议。
  - 只有建议时直接发布；有错误或提醒时先列出来，可以点「去修改」定位到对应模块，也可以「仍然发布」。
- **活动排期**（工具栏的 📅）：
  - 从接下来的活动生成活动版本（自动装修 + 活动文案，限时抢购截止到活动结束），也可以把当前草稿排期到某个时间段。
  - 到开始时间自动上线，结束后恢复原来的样子。活动进行中商家自己发布的修改会保留，结束时不会被覆盖。活动进行中点「结束」会马上恢复。
  - 打开「自动准备活动版本」后，活动进入准备期时会自动生成活动版本，状态为「待确认」，首页待办会提醒，确认后才会上线。
  - 每次上线和恢复都会记入历史版本。
  - 定时任务：`lumee:theme-schedules` 每 5 分钟处理上线和结束，每天 05:20 带 `--prepare` 准备新的活动版本。时间按店铺时区。

## AI 装修

代码在 `backend/app/Themes/AiDesigner.php`，编辑器里是「AI 助手」标签（`admin/src/components/theme/AiDesignPanel.vue`）。使用获客雷达里配置的 Claude Key。

- **一句话生成 / 修改**：选择「从头生成」或「修改这个页面」，用中文描述需求，例如「给巴西站做母亲节首页，温暖一点，主推项链」。作用于编辑器当前装修的页面（首页、商品页、分类页、购物车、活动页）和当前站点（主站点或某个市场）。
  - Claude 只返回主题里有的模块和字段（不写 HTML、CSS），结果都经过 `ThemeService::sanitize` 校验。
  - 商品、分类、折扣码只能从系统给出的候选清单里选（这个市场在卖的商品、已发布的分类、正在生效的折扣码），清单外的会被丢掉。图片字段 AI 不能改。
  - 文案用市场的语言写，按当地习惯写而不是逐字翻译；提到运费、退货、分期、支付、关税时，只能用系统给的真实数字。品牌规范的语气和禁用词也会带上。
  - 在市场里，跟随主站点的页面（商品页等）只能改字段内容，不能增删模块；首页结构变了就成为这个市场自己的首页。
- **方案 → 预览 → 应用**：生成的是方案，不会直接保存。预览可以在「修改前 / 修改后」之间切换（真实店铺页面，签名预览链接加 `&_proposal=…`，方案保存 30 分钟）。点「应用到草稿」才写入草稿，同时把应用前的草稿存为历史版本（来源 AI），可以一键恢复。AI 永远不会发布。
- **AI 检查**：先运行装修检查，再请 Claude 给出 3–6 条针对这个市场的改进建议，可以点「去看看」定位到模块。
- **做其他市场的版本**：把当前站点的首页按目标市场的语言和购物习惯重写，保存为目标市场的草稿（自己的首页），改写前的草稿存为历史版本。
- **AI 首屏背景**：「从头生成」时可以勾选「用 AI 生成首屏背景图」。系统先用热卖商品合成横幅，再交给图片生成服务（内容工坊里配置的 OpenAI）只替换背景、保留商品卡片，占用图片额度；没有配置或失败时使用合成横幅。
- **额度**：每个店铺每月 100 次 AI 装修请求（`settings.design.ai_quota`），编辑器里显示剩余次数。
- 装修检查新增一项：文案用了品牌规范里的禁用词时报错。

## 装修效果与 A/B 测试

代码在 `backend/app/Themes/DesignExperiments.php`、`DesignInsights.php`，后台页面是「在线商店 › 装修效果」（`admin/src/views/online-store/DesignPerformanceView.vue`）。

- **A/B 测试这个草稿**：编辑器顶部的烧瓶按钮（正在使用的主题、有未发布的修改时出现）。草稿冻结为 B 版，线上设计是 A 版，访客按 `lm_v` 访客 id 各分一半，同一位访客始终看到同一版；分组记在访问记录的 `design_experiment_id`、`design_arm` 上。爬虫和编辑器预览不参与。每个站点（主站点或某个市场）同时只能有一个测试；活动排期上线会停止测试。
- **结果和决定**：看板显示两个版本的访问、加购率、转化率、订单和每次访问收入（按基础货币）。每个版本至少 200 次访问且转化率差异显著（p < 0.05）时提示可以决定。「采用 B 版」发布 B 并存为历史版本；「保留 A 版」或「停止」不改线上设计。
- **各站点表现**：每个站点的跳出率、加购率、转化率、每次访问收入、手机占比、首页跳出等，和上一个同样长度的时段对比，并列出期间的设计改动。
- **每周建议**：`php artisan lumee:design-insights` 每周一 06:00 运行，规则发现 + Claude 建议（需要获客雷达里的 Claude Key，占用 AI 装修额度），结果存在 `design_insights`，每个站点每周一条。测试结果同时检验转化率和每次访问收入；还没有结论时，按目前的差距估算每个版本大约还需要多少访问；测试超过 28 天仍然差别很小时，建议停止并保留 A 版。配置了 Claude Key 时，每条建议旁有「让 AI 按这条修改」，会打开对应站点的装修编辑器，AI 助手里已经填好这条建议，生成方案后照常预览、再决定是否应用。

## 前台无障碍与 SEO

- 每个页面只有一个主标题（h1）：首页以首屏大图开头时用它的标题，否则放一个屏幕上看不见、但搜索引擎和读屏软件能读到的店铺名。
- 结构化数据：首页有 Organization 和 WebSite（含站内搜索）；商品页有 Product（每个规格的价格和库存；没有填品牌时用店铺名）；博客文章有 Article。
- 次要文字（灰色说明、划线价、页脚）自动保证和背景至少 4.5:1 的对比度（WCAG AA）。商家选的品牌色不会被自动修改，按钮对比度低于 3:1 时由装修检查提醒。
- 可点击的图标（页头的搜索、收藏、账户、购物袋，轮播圆点）至少 24×24 像素。

## 安全响应头

所有后端响应（店铺前台和 API）都带：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、关闭摄像头/麦克风/定位的 `Permissions-Policy`，HTTPS 下加 HSTS。店铺页面只允许被店铺自己和商家后台嵌入（装修编辑器预览要用，后台地址来自 `LUMEE_ADMIN_URL`，正式环境要设成后台的真实地址），其他响应一律不允许被嵌入，防止点击劫持。后台静态站点的同类响应头在 `.makeserver/docker/admin.Caddyfile` 里（后台不允许被任何页面嵌入）。

## AI 导购

后台「在线商店 › AI 导购」开启后，店铺右下角出现聊天按钮（代码在 `backend/app/Assistant/ShoppingAssistant.php`）。

- 买家用任何语言提问（尺码、材质、运费、付款、退货、送礼推荐等），用当前站点的语言回答，并附上推荐商品卡片（最多 4 个）。
- AI 只能从系统挑出的候选商品里推荐（按问题关键词搜索、买家正在看的商品、最新在售商品，只含当前市场在售的商品），价格、库存、规格、运费、付款方式和退换货等政策页内容都由系统提供；AI 返回的不在候选里的商品会被丢掉。不会出现其他店铺的商品。
- 对话只保存在买家当前的浏览器标签页里，每次提问带上最近几轮。后台能看到最近 50 个问题、回答和推荐了哪些商品。
- 使用获客雷达里配置的 Claude Key（模型 `claude-opus-5-5`，低推理强度，带拒答时的自动回退），费用计入商家自己的 Claude 账户。每月回答上限默认 1000 次（只统计成功的回答），用完后按钮自动隐藏，下个月恢复。每个访客每分钟最多 20 次提问。
- 可以自定义开场白；留空时按买家语言显示默认开场白。

## 店铺装修（主题编辑器）

后台入口是「在线商店 › 主题」（主题库），点某个主题的「自定义」进入编辑器：左侧编辑，右侧实时预览，用法类似 Shopify 的主题编辑器。

### 主题库

内置四套主题，都可以在「添加主题」里选：**Aurora**（轻奢珠宝）、**Fresh**（清爽绿白）、**Bold**（高密度促销：黑白配红色点缀、直角、窄体粗体大写标题，适合快时尚和大促）、**Luxe**（极简高级：大量留白、细线条、高对比衬线字体）。Fresh、Bold、Luxe 复用 Aurora 的页面和全部模块，只换样式（`resources/views/themes/{fresh,bold,luxe}/layout.blade.php`），所以市场装修、自动装修、AI 装修、风格包对四套主题都适用。

参照店匠和 Shopify 的「模板库」：一个店铺可以保存多个主题（最多 20 个），只有一个在使用。

- **使用中的主题**：页面顶部的大卡片，左边是店铺首页的实时缩略图，右边是名称、基于哪个模板、上次发布时间和配色，以及「自定义」「预览」按钮。
- **主题库**：其他主题（还没发布，买家看不到），每个都可以：
  - 发布、自定义、预览；
  - 复制、重命名、导出主题包、删除。使用中的主题不能删除。
- **添加主题**：
  - 从模板添加（Aurora、Fresh）；
  - 导入主题包（Lumée 导出的 .zip）；
  - 从 Shopify 主题导入。
- **数据结构**：`store_themes` 每行是主题库里的一个主题，`theme` 列是它基于的模板；`stores.theme_id` 指向使用中的那一个。老店铺没有 `theme_id` 时，按模板名找到它原来的主题，并在首次打开主题库时固定下来。

### 导出与导入主题包

- **导出**：生成一个 .zip，里面有：
  - `theme.json`：格式标记 `lumee-theme`、版本、名称、基于的模板、全部设置和首页模块；
  - `images/`：主题用到的图片；
  - 分类按 handle 记录。
- **导入**：可以导入到任何店铺。
  - 图片会重新保存为本店铺的图片（只接受 JPG / PNG / WebP / GIF，单张不超过 10MB）。
  - 分类按 handle 匹配本店铺的分类，匹配不到的模块会显示最新商品。
  - 所有内容都会按主题结构重新校验，导入后放进主题库，不会自动发布。
- **安全**：压缩包在内存中按文件名读取，不会解压到磁盘；只读取需要的 JSON 和图片，并限制每个文件的大小。上传文件最大 50MB。

### 从 Shopify 主题导入

在 Shopify 后台「在线商店 › 主题 › 操作 › 下载主题文件」得到 .zip，上传后选择转换到哪个模板（`ShopifyThemeConverter`）。也可以只上传 `settings_data.json` 或 `templates/index.json`。

- **可以转换的**：商家在 Shopify 主题编辑器里设置的内容。
  - 颜色：支持 Online Store 2.0 的配色方案（color_schemes）、旧版 Dawn 和 Debut 的颜色设置。
  - 字体：只有在可选字体里的才会用上，否则使用主题默认字体。
  - 公告栏：支持 `header-group.json` 和旧版的页头设置。
  - 首页模块：

    | Shopify 模块 | 转换为 |
    |---|---|
    | image-banner、slideshow | 首屏大图 |
    | featured-collection | 精选商品（按 handle 匹配分类） |
    | collection-list | 分类展示 |
    | image-with-text、multirow | 图文介绍 |
    | rich-text | 文字段落 |
    | newsletter、email-signup-banner | 邮件订阅 |
    | multicolumn | 服务亮点（三栏） |
    | collapsible-content | 常见问题 |
    | video | 视频 |
    | testimonials | 顾客评价 |

  - 其他：模块顺序和隐藏状态会保留；富文本会转成纯文本；`shopify://collections/…` 这类站内链接会转成本站路径。
- **不能转换的**：Liquid 代码和自定义模块（例如 custom-liquid）无法运行，不会导入。Shopify 文件库里的图片无法下载，需要在编辑器里重新上传。
- **转换报告**：导入后会列出哪些模块转换成了什么、哪些没有转换，以及需要注意的事项。

### 编辑器

- 编辑主站点时，被某些国家站点单独设置过的字段下面会提示“某某站点单独设置了这一项，这里的修改不会影响这些站点”；有国家站点用了自己的首页时，首页顶部也会提示。

- **主题结构**：每个主题在 `backend/config/themes.php` 里声明三样东西——全局设置（颜色、字体、页头、商品页、页脚）、可以添加的首页模块，以及新店铺默认的首页模块。后台编辑表单根据这份声明自动生成；服务端也按它校验所有保存的值，不在声明里的字段不会被保存。
  - **新增模块的方法**：在 `sections` 里加一项定义，再新建对应的模板 `resources/views/themes/aurora/sections/{类型}.blade.php`。
- **首页模块**：共 10 种——首屏大图、精选商品、分类展示、图文介绍、文字段落、邮件订阅、服务亮点、常见问题（可折叠）、视频（YouTube / Vimeo，只嵌入这两个网站，使用 youtube-nocookie）、顾客评价。添加模块时会显示每种模块的用途说明。
- **编辑操作**：
  - 撤销 / 重做：按钮或 Ctrl+Z / Ctrl+Y；连续输入算一步，在输入框里按 Ctrl+Z 撤销的是输入框里的文字。
  - 复制模块。
  - 拖动排序、隐藏。
- **草稿与发布**：编辑器修改后会自动保存为草稿，买家看不到；点击「发布」后才会上线；「放弃修改」会恢复到上一次发布的版本。
- **预览**：预览页的地址带有签名的 `_preview` 令牌，只读、2 小时后过期，不会被搜索引擎收录。在预览里点击某个模块，左侧会直接打开它的设置。
- **安全**：
  - 颜色只接受 `#RRGGBB` 格式，字体只能从固定列表中选择。
  - 链接只允许站内路径（以 `/` 开头）、页面锚点（`#`）和 `http(s)://` 开头的地址。
  - 所有文字在显示时都会转义，防止注入脚本。
  - 主题图片只能使用本店铺上传的图片。

## 前台速度与分类筛选

- **图片多尺寸**：上传的图片在前台按需生成 160–1920px 几种宽度的 WebP（`/_img/{宽度}/{路径}`，第一次请求时生成，存在媒体盘的 `_variants/` 下，浏览器缓存一年）。主题里的商品卡片、首屏、轮播、商品主图等都带 `srcset`，手机只下载需要的尺寸；首屏图 `fetchpriority="high"`，其余延迟加载。代码在 `backend/app/Media/Img.php`。删除或替换图片时，生成的尺寸一起删除。
- **页面缓存**：没有登录、购物袋为空的访客，首页、商品页、分类页、活动页、博客由缓存直接返回（默认 180 秒，`LUMEE_PAGE_CACHE_TTL`；`LUMEE_PAGE_CACHE=false` 关闭）。缓存按站点、语言、币种、访客国家、设计 A/B 分组区分；正在做商品 A/B 测试的商品页、编辑器预览、有提示消息的页面不缓存。每个访客的 CSRF 令牌会替换回去，命中缓存的商品页仍然计入商品浏览。后台或开放 API 的任何修改、以及商品、主题、市场等数据保存时，立即清掉这家店的缓存。响应头 `X-Page-Cache: HIT / MISS` 可以用来检查。代码在 `backend/app/Http/Middleware/CacheStorefrontPage.php`。
- **分类页筛选**：按规格（尺码、颜色等，用前台语言显示）、商品类型、有货、价格区间（访客币种）筛选；同组多选为“或”，不同组为“且”，规格按同一个规格组合判断（选了 7 号 + 金色，只有真的有“金色 7 号”的商品才显示）。每个选项显示数量，已选条件显示成可以单独删除的标签。电脑上筛选在左侧，手机上收进「筛选」按钮。商品列表模块可以关闭筛选（「显示筛选」）。超过 3000 个商品的分类不显示筛选。代码在 `backend/app/Catalog/CollectionFilters.php`。搜索结果页使用同一套筛选。
- **用 Google 登录**：买家在登录和注册页可以「用 Google 继续」。整个平台共用一个 Google OAuth 客户端：在 Google Cloud 控制台创建「Web 应用」类型的 OAuth 客户端，授权回调地址填 `{APP_URL}/auth/google/callback`（或 `GOOGLE_LOGIN_REDIRECT_HOST` 指定的地址），然后设置 `GOOGLE_LOGIN_CLIENT_ID`、`GOOGLE_LOGIN_CLIENT_SECRET`。没设置时按钮不显示。Google 先回到平台地址，平台用一次性凭证（2 分钟、只能用一次、必须是发起登录的同一个浏览器和同一家店）把买家送回店铺登录；已验证的邮箱会关联到已有的客户记录。代码在 `backend/app/Http/Controllers/Storefront/GoogleLoginController.php`。
- **添加到手机桌面（PWA）**：每家店都有 `/manifest.webmanifest`，图标用店铺 Logo 和配色自动生成（`/pwa-icon/192.png`、`512.png`、苹果用 `180.png`）。`/sw.js` 只在断网时显示一个离线页面（`/offline`），不缓存任何页面、购物车或账户数据。编辑器预览里不注册。
- **最近浏览**：新模块「最近浏览」（首页、商品页、分类页、购物车、活动页都能放；新主题的商品页默认带上）。浏览记录只存在访客自己的浏览器里（`localStorage`），由页面上的脚本读取后显示，所以不影响页面缓存。商品价格按当前站点（市场、币种、语言）显示。
- **欧盟最低价规则**：每个规格的价格变动记录在 `variant_price_history`。欧盟站点（市场的国家里有欧盟国家，或主站用欧元）商品打折显示划线价时，价格下面会写“降价前 30 天内的最低价”（欧盟价格指令要求）。按 30 天前起算、包含当时生效的价格；没有更早价格记录的规格不显示。代码在 `backend/app/Catalog/PriceHistory.php`。市场里单独设置了固定价的规格，按“这个市场的买家实际看到的价格”计算：固定价存在时用固定价，删除后跟随店铺价格换算（固定价的变动也记在 `variant_price_history`，`market_id` 不为空）。

## 商品图片与多规格

- **图片**：在商品编辑页拖拽或点击上传，单张不超过 10MB，最多 20 张。可以拖动排序，第一张作为主图。
  - 存放位置：`stores/{店铺ID}/products/`，使用的磁盘由 `.env` 中的 `LUMEE_MEDIA_DISK` 决定；本地默认是 `public`，需要先运行一次 `php artisan storage:link`。
  - 上传后没有保存到商品里的图片，每天 03:30 会被自动清理。本地需要另开一个终端运行 `php artisan schedule:work`；也可以手动执行 `php artisan lumee:prune-images`。
- **规格**：每件商品最多 3 个规格（如 材质 / 尺寸 / 颜色）。系统会自动生成所有规格组合，最多 100 个 SKU；每个 SKU 可以单独设置价格、原价、SKU 编码、库存和规格图片。
  - 保存时，已有的 SKU 会保留原来的 ID，购物车和历史订单里的关联都不会断。
- **店铺前台**：商品页显示主图和缩略图，买家用按钮选择规格，价格、库存、图片会跟着切换；已售罄的规格显示为划线。网址会带上 `?variant=ID`，可以直接分享某个规格。
- `brand/demo/` 里有两张演示用的商品图。

## 购物车与结账

买家的购买流程：商品页 → 购物车 `/cart` → 结账 `/checkout` → 订单状态页 `/orders/{token}`

- **购物车**：通过 cookie 识别。cookie 按域名隔离，所以每家店的购物车互不影响。
- **下单**：在一个数据库事务里锁住库存行，同时完成校验库存、扣库存和生成订单号，所以不会超卖。订单号每家店各自从 #1001 开始编号。
- **运费**：新建店铺时会自动生成 3 档运费：标准 $9.90、加急 $24.90、满 $99 包邮。
- **支付方式**（`app/Payments/`）：
  - `test`：测试支付，下单后立即标记为已付款。只在本地使用，由 `.env` 中的 `LUMEE_TEST_PAYMENTS=true` 开启。
  - `manual`：银行转账。订单保持「待付款」状态，商家在后台手动标记为已付款。
  - `stripe`：跳转到 Stripe 托管的付款页，卡号不会经过我们的服务器。付款以 webhook 回调为准，不以浏览器跳转为准。
    - 启用方法：在 `.env` 中填写 `STRIPE_SECRET` 和 `STRIPE_WEBHOOK_SECRET`。
    - Webhook 地址填 `/webhooks/stripe`，监听 `checkout.session.completed` 事件。
    - 本地调试可以用 `stripe listen --forward-to localhost:8000/webhooks/stripe`。
    - 开启 Stripe Connect（`STRIPE_CONNECT=true`）后，信用卡付款进入商家自己的 Stripe 账户（见「运费与收款」）。PayPal 目前仍然进入平台账户。

## 开放 API 与 Webhooks

完整文档见 [docs/api.md](docs/api.md)。

- **访问令牌**（后台「设置 → 开发者」）：
  - 商家为 ERP、仓库系统或自己的程序创建令牌，按需选择权限：读取商品、管理商品、修改库存、读取订单、处理订单、读取客户。
  - 令牌格式是 `lm_…`，只在创建时显示一次，数据库只保存 SHA-256 哈希；随时可以撤销。
- **REST API v1**（`/api/v1`）：
  - 接口：商品增删改查、分类、库存设置或增减（按规格 ID 或 SKU）、订单列表和详情、发货和修改物流、客户列表和详情。
  - 实现：直接复用后台的控制器和校验规则，所以行为和后台完全一致。
  - 认证中间件 `AuthenticateApiToken` 根据令牌设置当前店铺，所有查询都按店铺隔离。
  - 错误信息为英文。每个令牌每分钟最多 120 次请求；店铺暂停时返回 402，缺少权限时返回 403。
- **Webhooks**（`App\Webhooks`）：
  - 事件：`orders/create`、`orders/paid`、`orders/fulfilled`、`orders/cancelled`、`orders/refunded`，`products/create`、`products/update`、`products/delete`，`customers/create`。
  - 推送内容和 REST API 返回的 JSON 相同。签名请求头是 `X-Lumee-Hmac-Sha256: base64(hmac_sha256(请求体, 密钥))`，`X-Lumee-Event-Id` 可以用来去重。
  - 发送时机：数据库事务提交后才进入队列。
  - 重试：失败后依次在 1 分钟、5 分钟、30 分钟、2 小时、6 小时后重试；连续 10 个事件都失败时，订阅会自动停用，重新启用后计数清零。
  - 后台可以发送测试事件、查看最近 50 条发送记录、重新发送某个事件。
  - 防 SSRF：接收地址必须是 https 公网地址，发送时固定连接到已经校验过的 IP，也不跟随跳转。
  - 商品批量导入不会触发 `products/*` 事件（避免一次推送上千条）。
- **OAuth 应用市场**（`App\Apps\OAuth`）：
  - **开发者**：任何账号都可以在「我的应用（开发者）」注册应用，得到 client ID、client secret（只显示一次，可以重新生成）和签名密钥。
    - 草稿状态的应用只能由开发者自己安装测试。
    - 提交审核、平台在运营后台「应用审核」通过后，应用才会上架；上架后再申请更多权限，需要重新审核。
  - **授权流程**：标准 OAuth 2.0 授权码流程，支持 PKCE。
    - 商家在后台 `/oauth/authorize` 页面选择店铺、确认权限。没有登录时会先登录，登录后回到授权页。
    - 应用服务器用授权码在 `/api/oauth/token` 换取店铺令牌。授权码 10 分钟内有效，只能用一次；被重复使用时，会吊销它换出的令牌。
    - 回调地址必须和登记的完全一致，申请的权限不能超出登记范围。
  - **令牌**：应用拿到的就是普通的店铺 API 令牌（权限、限流、店铺隔离都一样），关联到这次安装，每个店铺只保留一个。
  - **Webhook**：应用通过 `/api/v1/webhooks` 管理自己的订阅，订阅事件需要对应的读取权限。
  - **商家「应用」页**：显示已安装的应用（可以打开、卸载）和应用市场。
    - 卸载后令牌立即失效、应用的 Webhook 被删除，并向应用的卸载通知地址发送签名通知。
  - **其他**：「设置 → 开发者」里只显示商家自己创建的令牌和 Webhook，不包括应用的。

## 多店铺管理

一个账号可以开多家店铺（例如按国家或品牌分店），在后台左上角的店铺菜单里切换。

- **新建店铺**（`POST /api/admin/stores`）：
  - 填写名称和结算币种即可。
  - 每家店铺有独立的商品、订单、域名、套餐和 14 天试用。
  - 每个账号最多拥有 10 家店铺（`OrganizationController::MAX_OWNED`）。
- **所有店铺概览**（后台 `/stores`，`GET /api/admin/organization/overview`）：
  - 每家店铺的状态、今日销售额、所选时间段的销售额、订单数和客单价。
  - 总销售额按所选币种换算；缺少汇率的店铺不计入总额，并会提示。
  - 跨店铺的最近 10 笔订单，点击会切换到对应店铺并打开订单。
  - 员工只能看到自己有「数据分析」权限的店铺；最近订单只包含有「订单」权限的店铺。
- **复制商品到其他店铺**（商品列表勾选后点「复制到其他店铺」，`POST /api/admin/products/copy`）：
  - 复制内容：规格、SKU、价格、SEO 和图片。图片文件会真正复制一份，两家店铺互不影响。
  - 币种不同时，价格可以保持数字不变，也可以按当前汇率换算。
  - 库存默认为 0，商品默认复制为草稿；这两项都可以选择保留原值。
  - 分类不会复制。一次最多复制 100 件。
  - 目标店铺必须是你有商品权限的店铺，且没有暂停营业。
  - 实现在 `App\Services\ProductCopier`：临时把当前店铺切到目标店铺，再走 `ProductService::save`，复制完成后切回。

## 后台首页

首页（`DashboardView`）是店铺的经营概况，可切换今天、近 7 天、近 30 天：

- **核心指标**：销售额、订单数、访客数、转化率、客单价，带小趋势图和与上一周期的对比；右上角显示实时在线人数。
- **图表**：销售额 / 访问趋势图（本期和上期对比）、转化漏斗。
- **排行**：流量来源、地区分布、热销商品，各取前 5。
- **最近订单**：最新 6 笔，点击进入订单详情。
- **待办事项**（`DashboardController`）：待发货、待付款、待处理的拒付、近 7 天可挽回的弃单、库存不足（上架商品库存 ≤ 5）、待审核评论，点击直达对应页面。
- **开店指引**：只在还没有商品或订单时显示。

员工只看到自己有权限的模块；没有「数据分析」权限的员工只看到订单、商品、客户数量和待办事项。

## 数据分析（访客与转化）

后台「数据分析」页面（`AnalyticsController`）按店铺时区统计，每项指标都和上一个同长周期对比。

- **时间范围**：今天（按小时）、昨天、近 7 / 30 / 90 天，或自定义日期（最长 366 天）。
- **核心指标**：销售额（已付款订单扣除退款）、订单数、客单价、访客数、转化率、新客户，以及实时在线人数（最近 5 分钟）。
- **趋势图**：销售额、订单数、访问三选一，本期为绿色实线，上期为灰色虚线。
- **转化漏斗**：访问 → 浏览商品 → 加入购物车 → 进入结账 → 完成付款，显示每一步的继续率和流失人数。
- **流量来源**：直接访问、自然搜索、社交媒体、邮件、付费广告、外部网站，各自的访问、转化率和销售额。
- **地区分布**：访问按访客地区统计，订单和销售额按收货国家统计。
- **其他报表**：设备与浏览器、商品分析（浏览、加购、加购率、售出、销售额、转化率）、热门着陆页、UTM 推广活动、来源网站、新老客户与复购率、下单时段。

访客数据由店铺前台自己记录（`App\Analytics\Visits`，中间件 `store.analytics`）：

- **Cookie**：用两个第一方 Cookie 区分访问和访客：
  - `lm_s`：一次访问，30 分钟无操作后失效；
  - `lm_v`：访客，有效期 1 年，用来识别回访。
- **不存个人信息**：不保存 IP 或其他个人信息。
- **不计入的访问**：搜索引擎爬虫、链接预览、浏览器预加载、主题编辑器预览都不计入。
- **来源判断**：先看 UTM 参数，再看广告点击参数（`gclid`、`msclkid`、`ttclid`），最后看来源网址。
- **邮件营销链接**：会自动加上 `utm_medium=email`、`utm_campaign=campaign-<ID>`。
- **访客地区**：优先读取 CDN 提供的国家请求头（`CF-IPCountry`、`CloudFront-Viewer-Country`、`X-Country-Code` 等）；没有时根据浏览器语言估算（例如 `en-US` → 美国）。
  - 想要准确的地区数据，建议在 Cloudflare 后面部署，或者让反向代理写入 `X-Country-Code`。
- **完成付款的判定**：本次访问中下的订单已付款，才算完成付款。
- **商品数据**：每个商品每天的浏览和加购次数存在 `analytics_product_stats` 表里。

页面底部的「客户留存」（`RetentionController`）把买家按首次付款的月份分组，显示之后每个月再次购买的比例（近 6 或 12 个月），并给出复购客户占比、人均订单数和首单到第二单的天数（中位数）。买家按订单邮箱识别，包含游客下单，不受页面时间范围影响。

右上角「导出报表」把当前时间范围内的所有报表导出为一个 CSV 文件（UTF-8，Excel 可直接打开）。

## 多租户的关键约定

- 店铺级数据表都有 `store_id` 字段，对应的 Model 必须使用 `App\Tenancy\BelongsToStore` trait。它会自动给查询加上店铺过滤，并在新建记录时自动写入 `store_id`。
- 当前店铺的识别方式：
  - 后台 API：由 `ResolveAdminStore` 读取请求头 `X-Store-Id`，并校验当前用户是否属于该店铺。
  - 店铺前台：由 `ResolveStorefrontStore` 根据访问的域名识别。
- 这两个中间件都排在路由模型绑定之前，所以通过 `/products/{id}` 这类地址无法读到其他店铺的数据。
- 金额一律以「分」为单位存成整数，读写统一通过 `App\Support\Money` 处理。

- **PayPal 商家独立收款**：PayPal 付款目前进入平台账户。要让商家用自己的 PayPal 账户收款，需要申请 PayPal 的平台合作伙伴（Partner）资格并接入 Partner Referrals 开户流程；这一步需要 PayPal 审核，无法只靠代码完成。
- **更多本地支付**：Airwallex 支持的本地支付方式由 Airwallex 后台开启后自动出现。Razorpay 目前使用平台账户收款，商家要用自己的 Razorpay 账户收款，需要接入 Razorpay Partner（Route）。
- **AI 功能的范围**：商品文案建议（内容工坊）、店铺文案翻译、AI 装修、每周装修建议和 AI 导购都已可用，统一使用获客雷达里配置的 Claude Key，通过已安装的 Anthropic 官方 PHP SDK（`anthropic-ai/sdk`）调用。
- **美国以外的精确税费**：Stripe Tax 目前只用于美国订单；加拿大各省、欧盟一站式申报（OSS）等仍按手动税率计算。
