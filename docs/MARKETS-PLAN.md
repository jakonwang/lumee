# 多国家 · 多品类运营规划（参考 SHEIN 模式）

> 目标：一个后台管理多个国家站点，每个站点都有适合当地的商品、价格、币种、主题和支付方式。选品有数据支撑，采集和上架可以批量完成，同时有 B 端批发能力。
> 本文对照现有代码（Laravel 12 + Vue 3）写成，说明哪些可以直接复用，哪些需要新建。

---

## 0. 先想清楚：SHEIN 强在哪，我们能学到什么

SHEIN 的网站本身不复杂，难学的是背后这套循环：

```
看趋势 → 少量上新（每款先做很少的货）→ 看 7–14 天的数据 → 卖得好的加单、加广告 → 卖不动的下架
          ↑______________________________________________________________|
```

1. **按数据选品**：趋势数据、站内搜索词、竞品排行，加上 AI 分析。
2. **小批量测款**：一次上很多新款，每款投入很少，让数据选出爆款。
3. **按国家运营**：同一件商品，在不同国家的价格、尺码、模特图、主推位置、活动节点都不一样。
4. **供应链快速补货**：这一点软件替代不了，但系统可以把“哪款该补、补多少”算出来。

**结论**：要做的不只是“多国家模板”。核心是两件事：一是用「市场（Market）」把站点拆开管理，二是把「选品 → 采集 → 上架 → 测款 → 汰换」做成一个闭环。

## 1. 现状盘点：已有能力与缺口

| 需求 | 现有代码 | 缺口 |
|---|---|---|
| 多币种 | `app/Currency/Presentment.php`：按 IP 识别国家，**只换算显示价格**，结账仍用店铺币种 | 需要**用当地币种结算**；每个市场单独定价，不能只按汇率换算 |
| 多语言 | `app/I18n/Localization.php`：`/fr/...` 语言前缀和字段级翻译 | 语言和国家是两回事：要能区分 `/us`、`/mx`（同为西语）、`/br` |
| 主题 | `StoreTheme` 一个店铺只有一套已发布主题 | 每个市场要有自己的主题实例和首页内容 |
| 商品 | `products` / `product_variants`，价格存一个币种 | 缺少：成本、重量、HS 编码、货源、**每个市场是否上架、每个市场的价格** |
| 导入 | `app/Imports/ProductCsv.php`（Shopify CSV 格式）+ 队列任务 | 不能按链接采集，也没有 AI 清洗和批量定价 |
| 选品 | 没有 | 全部新建 |
| B 端 | `app/B2B/`（企业客户、价格表、报价单）、`app/Pricing/PriceLists.php`、获客雷达 | 价格表没有按市场和币种区分；获客雷达找到的客户和批发目录没有打通 |
| AI / 抓取 | `app/LeadFinder/LeadAi.php`、`SafeFetcher.php`、队列模式 | **可以直接复用**到采集和选品分析 |
| 运费 / 税 | `ShippingZone`、`TaxRate` | 缺少：按市场的关税和进口税规则（美国、欧盟 IOSS、巴西） |

## 2. 核心概念：Market（市场）

所有按国家区分的配置都挂在「市场」上。设计参考 Shopify Markets，并按 SHEIN 的做法加强。

```
Store（店铺）
 └── Market（市场）×N：美国站 / 欧洲站 / 巴西站 / 墨西哥站 / 东南亚各国站 …
      ├── 覆盖国家：["US"] 或 ["DE","FR","IT","ES","NL",…]
      ├── 结算币种：USD / EUR / BRL / MXN / IDR / PHP / THB / MYR / VND / SGD
      ├── 语言：en / es-MX / pt-BR / de / fr / id / th / vi …
      ├── 访问地址：子目录 /us/、/br/，或子域名 us.xxx.com，或独立域名 xxx.com.br
      ├── 主题实例：自己的首页、导航、Banner、活动页
      ├── 商品范围：哪些商品在这个市场上架（商品 × 市场）
      ├── 定价策略：成本 → 当地售价的公式、尾数规则、折扣上限
      ├── 支付方式：当地常用的支付方式
      ├── 物流和税：运费模板、关税和进口税规则、包邮门槛
      └── 尺码换算、计量单位、日期和数字格式
```

### 2.1 访问和识别
- 访客第一次进入时，按 IP 国家（Cloudflare 的 `CF-IPCountry`，现有代码已在用）推荐市场，**弹窗询问，不强制跳转**（对 SEO 和用户都更友好）。
- 每个市场的页面都输出 `hreflang` 和独立的 sitemap，让 Google 美国站收录 `/us/`，Google 巴西站收录 `/br/`。
- 路由（已实现）：`/{语言}-{市场后缀}/...`，例如 `/en-us/`、`/es-mx/`、`/fr-eu/`。不用 `/us/` 这种写法，是因为市场后缀会和 `/de/`、`/fr/` 这类语言前缀冲突。

### 2.2 真正的多币种结算（改动最大的一项）
现在 `Presentment` 只换算显示价格。要改成：
- 每个市场的商品价格是**单独存储的当地价格**，不是“美元价格 × 汇率”。
- 购物车、订单、支付都用市场币种；订单保存“下单时的汇率”，用于换算成本和利润。
- Stripe、PayPal、Airwallex 都支持多币种收款，只要在创建支付时传入市场币种。

### 2.3 当地化价格
| 市场 | 价格习惯示例 |
|---|---|
| 美国 | $12.99、$19.99，常用“满 $49 包邮” |
| 欧洲 | 12,99 €，价格**含税**（VAT），德国、法国的价格可以不同 |
| 巴西 | R$ 49,90，突出**分期**：“3x de R$ 16,63 sem juros”（3 期免息） |
| 墨西哥 | $299 MXN，常用 OXXO 便利店付款 |
| 印尼 / 越南 | Rp 89.000、189.000₫（整千） |
| 泰国 / 菲律宾 / 马来西亚 | ฿299、₱499、RM39 |

## 3. 模块规划

### 模块 A：选品雷达（找什么好卖）

**目的**：针对每个市场，回答“哪些品类、哪些款式，在这个国家现在值得上”。

**数据来源**（优先选合规、稳定的来源）：
| 类型 | 来源 | 说明 |
|---|---|---|
| 搜索趋势 | Google Trends（按国家） | 判断品类热度和季节性 |
| 社媒趋势 | TikTok Creative Center 热门商品和话题、Pinterest Trends、Meta 广告库 API | 看哪些商品在投广告、在火 |
| 电商排行 | Amazon Best Sellers / Movers & Shakers（通过 Keepa、Rainforest 等第三方 API 获取）、Shopee / Lazada / Mercado Livre 热销榜 | **不要自己硬爬**：容易被封，也有法律风险 |
| 竞品独立站 | Shopify 店铺公开的 `/products.json`、竞品上新速度 | 合规的公开数据 |
| 站内数据 | 站内搜索词（包括**搜了但没有结果的词**）、加购率、收藏、退货原因 | **最准的数据**，越用越准 |
| 货源 | 1688 / Alibaba 同款价格和起订量 | 用来算利润 |

**评分模型**（每个“候选品 × 市场”打一个 0–100 分，复用获客雷达的打分方式）：
- 需求热度（搜索量、排行）25%
- 趋势变化（近 4 周增速）20%
- 利润空间（当地售价 − 货价 − 运费 − 关税 − 平台和支付费）20%
- 竞争程度（同款数量、价格是否已经被打烂）15%
- 物流适配（重量、体积、是否带电、液体）10%
- 合规风险（美国 CPSIA / FCC、欧盟 CE / GPSR、巴西 ANATEL / INMETRO、带电产品）扣分项
- 文化适配（例如印尼、马来西亚对保守服饰的偏好；巴西尺码和身材差异）

**AI 分析**（复用 `LeadAi` 调用 Claude 的方式）：输入候选品和各市场数据，输出：
- 适合哪些市场，原因是什么；
- 建议售价区间（按当地价格习惯）；
- 当地语言标题、卖点、SEO 关键词；
- 风险提示（侵权、品牌词、合规认证）；
- 推荐的同类款式和组合销售。

**页面**：选品雷达首页（按市场切换）→ 热门品类榜 → 候选品列表（分数、趋势图、利润估算）→ 一键「加入采集」。

### 模块 B：采集中心（把商品拿过来）

**采集方式**（按推荐程度排序）：
1. **浏览器插件一键采集**（最推荐）：运营在 1688 / AliExpress / Temu / Amazon / Shopify 店铺页面点一下，插件读取页面上的商品数据，发回后台。用的是运营自己的浏览器，不会被反爬拦截，也最稳定。
2. **粘贴链接批量采集**：服务器去抓（复用 `SafeFetcher`）。适用于 Shopify / WooCommerce 店铺这类公开、结构化的数据；遇到反爬保护时只记录“未能读取”，**不去绕过**（和获客雷达的做法一致）。
3. **官方 API**：1688 开放平台、AliExpress 代发 API、供应商提供的数据文件（价格和库存可以自动同步）。
4. **CSV / Excel 导入**：现有 `ProductCsv` 继续保留。

**采集后的处理流程**（每一步都在队列里运行）：
```
原始数据 → 整理结构（规格、SKU、图片、尺码表、重量）
        → 查重（图片相似度 + 标题），防止重复上架
        → AI 清洗：去掉中文、品牌词和夸张宣传词，改写标题和描述，提取属性，按市场翻译
        → 图片处理：选主图、去水印检测、标出含中文的图片（提醒运营替换）
        → 品牌化优化：按品牌规范重写标题、处理图片、重排详情（见模块 B+）
        → 自动定价（见模块 C）
        → 进入「待审核商品池」
```

**商品池状态**：已采集 → 已清洗 → 已品牌化（内容分达标）→ 已定价 → 已审核 → 已上架（到哪些市场）→ 测款中 → 爆款 / 淘汰。

**需要注意**：图片和描述可能涉及版权；品牌商品有侵权风险。系统要做品牌词检测和侵权提示，并让运营确认后再上架。

> 采集只负责“把货拿进来”。拿进来的内容还是供应商的样子：标题堆满关键词，图片带水印和中文，详情是一长串截图。**要变成我们自己的品牌商品，必须经过下面的「内容工坊」。**

### 模块 B+：商品内容工坊（品牌化）

**目标**：每一件上架的商品，看起来都出自同一个品牌：标题有统一的命名规则，图片风格统一，详情页结构统一，语气一致，而且按市场做了当地化。顾客看不出这是采集来的商品。

#### B+.1 品牌规范（Brand Kit）：一切优化的依据
在后台设置一次，AI 和模板都按它来执行。每个市场可以覆盖部分设置。

| 项目 | 内容 | 示例 |
|---|---|---|
| 品牌定位 | 一句话定位、目标人群、价格带 | “给 25–35 岁都市女性的平价轻奢饰品” |
| 品牌语气 | 语气关键词、要用的词、禁用词 | 温暖、自信、简洁；禁用 “best quality”、“cheap”、“100% original”、感叹号连用 |
| 命名规则 | 标题结构、系列名、最大长度 | `[系列名] [核心品类] – [材质/卖点] \| [风格]` |
| 视觉规范 | 主图比例、背景色、留白、模特风格、Logo 位置、字体、滤镜色调 | 3:4 竖图（SHEIN 的比例）、#F7F5F2 浅暖灰背景、商品占画面 70% |
| 详情页模板 | 固定的模块顺序 | 卖点 → 细节图 → 材质和工艺 → 尺码表 → 保养 → 售后承诺 |
| 合规词库 | 各市场不能出现的说法 | 美国不能随便写 “hypoallergenic”；欧盟不能用没有依据的 “eco-friendly” |
| SKU 编码规则 | 自有编码，不暴露供应商货号 | `LM-NK-2611-GLD-16`（品牌-品类-年月-颜色-尺码） |

#### B+.2 标题优化
- **去掉供应商痕迹**：品牌词、“2026 新款爆款”、“工厂直销”、堆砌的关键词、中文和乱码。
- **按命名规则重写**，并按市场生成不同版本：
  - 美国：`Aurora Layered Necklace – 18K Gold Plated, Tarnish-Free | Minimalist`
  - 巴西：`Colar Aurora em Camadas – Banhado a Ouro 18K | Minimalista`
  - 不是直接翻译：每个市场用当地人真正会搜的词（来自选品雷达和站内搜索词）。
- **系列化命名**：同一批风格相近的商品归到同一个系列（如 “Aurora 系列”），比无规律的单品名更像品牌，也方便做系列页和组合销售。
- **SEO**：同时生成 SEO 标题（60 字符以内）、描述（155 字符以内）和网址（handle）。
- **长度和格式检查**：超长、全大写、重复词会自动标红。

#### B+.3 图片优化（工作量最大，也最能体现品牌感）

**处理流水线**（队列执行，每一步都保留原图，可以撤回）：
```
原图 → 质量检查（分辨率、模糊、是否有水印 / 中文 / 其他品牌 Logo）
     → 抠图去背景 → 按品牌规范换背景、统一比例和留白
     → 色彩校正（统一色调和白平衡）→ 放大和锐化（低分辨率图片）
     → 生成场景图和模特图（AI 生成，可选）→ 加品牌元素（可选：角标、Logo）
     → 按尺寸输出（主图 3:4、方图 1:1 给广告、竖图 9:16 给短视频平台）→ 压缩成 WebP / AVIF
```

**主图规则**：第一张必须是统一背景的商品图；第二张是模特或佩戴效果图；后面依次是细节、尺寸参照、包装图。系统会检查顺序和数量（例如至少 5 张），不够的会提示。

**按市场换模特图**：同一件商品，美国站用多元化模特，巴西站用拉美模特，东南亚站用亚洲模特，中东和印尼站用更保守的穿搭。这是 SHEIN 的做法，AI 生成模特图让这件事的成本变得很低。

**技术选型**（图片处理用专门的服务，Claude 负责“看”和“写”）：
| 能力 | 方案 |
|---|---|
| 抠图、去背景 | 自己部署开源的 rembg（免费），或者调用 remove.bg、Photoroom 的 API（效果更好，按张收费） |
| 放大、修复 | Real-ESRGAN（自己部署）或第三方 API |
| 场景图、模特图 | 图片生成模型的 API（做成可替换的接口，按效果和价格选择供应商） |
| 识别图片内容 | Claude 看图：判断角度、有没有水印和中文、是不是同款、给图片排序、写 alt 文字 |
| 基础处理 | PHP 安装 Imagick 扩展（裁剪、换背景、压缩），队列中执行 |

**重要原则**：**不做“去除别人的水印”这个功能。** 带别人水印的图片说明版权属于别人，去掉水印再用就是侵权。系统检测到水印时，只提示运营：“请向供应商要无水印原图 / 用 AI 重新生成场景图 / 自己拍摄”。真正长期做品牌，主力商品要逐步换成**自己拍的图**，系统里要能标记每张图的来源（供应商图 / AI 生成 / 自己拍摄）。

#### B+.4 详情页优化
- **从截图变成结构化内容**：供应商的详情大多是一长串图片。先用 Claude 看图，把图片里的文字信息（尺寸、材质、参数）提取成结构化的字段，再按品牌的详情页模板重新排版。
- **固定模块**：卖点（3–5 条，带图标）→ 细节图 → 材质和工艺 → 尺码表 / 尺寸说明 → 保养说明 → 发货和退换承诺 → 常见问题。
- **按市场当地化**：单位（英寸 / 厘米）、尺码体系（US / EU / BR）、退换政策、当地法规要求的说明（如欧盟 GPSR 要求的制造商和责任人信息、美国加州 Prop 65 警示）。
- **属性标准化**：材质、颜色、风格、场合、季节写成统一的属性值（不是自由文字），用于筛选、推荐和广告数据源（Google Merchant Center、Meta 商品目录）。

#### B+.5 内容质量评分和审核
每个商品有一个 **内容质量分（0–100）**，按市场分别计算，低于标准不能上架：

| 检查项 | 分值 |
|---|---|
| 标题符合命名规则、长度合适、没有禁用词 | 20 |
| 主图符合视觉规范、图片数量够、没有水印和中文 | 30 |
| 详情包含所有必填模块 | 20 |
| 属性填写完整（材质、颜色、尺码表…） | 15 |
| 当前市场的翻译完成并经过检查 | 10 |
| SEO 信息完整 | 5 |

- **审核流程**：AI 优化 → 运营检查（新旧内容对比，逐项采纳或修改）→ 主管抽查 → 上架。
- **版本记录**：每次修改都保存一个版本，可以对比和回退。
- **批量处理**：选中 200 件商品 → “按品牌规范优化标题和图片” → 后台排队处理 → 完成后逐个或批量审核。

#### B+.6 用数据持续优化
- **A/B 测试主图和标题**：同一件商品准备两张主图，各给一半访客看，7 天后用点击率和加购率决出胜者，自动替换。这一步接到模块 D 的测款看板。
- **找出拖后腿的内容**：点击率低于品类平均值 → 提示换主图；加购多但转化低 → 提示检查详情页和尺码表；退货原因多为“和图片不符” → 提示换成实拍图。
- **从评论里找卖点**：AI 汇总买家评论里提到最多的优点和问题，写回详情页的卖点和常见问题。

#### B+.7 品牌资产管理
- **素材库**：在现有 `store_media` 基础上，增加标签、来源（供应商 / AI / 自拍）、授权状态、所属商品和系列、使用位置。一张图被哪些商品和页面用到，一目了然。
- **系列管理**：系列有自己的故事、主视觉和系列页，商品归属到系列。
- **品牌包装和插卡**（线下部分）：系统记录每个商品对应的品牌包装和吊牌，给仓库打包时使用。

### 模块 C：定价引擎（每个市场一个价格）

```
当地售价 = 尾数规则(
   (货价(人民币) + 国内运费 + 国际运费(按重量和市场)
    + 关税和进口税(按市场规则) + 支付手续费 + 广告预算比例)
   ÷ (1 − 目标利润率) × 汇率
)
```
- 规则可以按 **市场 × 品类 × 标签** 设置。例如“巴西站的服装，利润率 45%，尾数 ,90”。
- 划线价（compare_at）按规则生成，但要设上限，避免违反欧盟“虚假折扣”的规定（欧盟要求原价参考过去 30 天的最低价）。
- 汇率变化超过一定幅度时，提醒重新定价，不自动改价。
- **关税规则要可以配置**，因为各国政策变化快（以下情况以当时的法规为准）：
  - 美国：2025 年起取消了小额包裹免税，按品类计算关税；
  - 欧盟：IOSS 申报的 VAT，以及小额包裹关税新规；
  - 巴西：Remessa Conforme 规定下的进口税 + ICMS 州税。
- 复用 `PriceLists` 的计算方式：先算出市场价，再叠加 B 端价格表的折扣。

### 模块 D：批量上架与测款

- **批量操作**：选中商品 → 选择市场 → 应用定价规则 → 选择分类 → 定时上架（例如每天上午 10 点上新 50 款）。
- **批量修改**：价格、标签、分类、在哪些市场上架、SEO。
- **测款看板**（SHEIN 的核心做法）：
  - 新品上架后 N 天内的曝光、点击率、加购率、转化率、退货率，**按市场分别统计**；
  - 自动标记：🔥 潜力款（加购率高于品类平均值的 2 倍）、❄️ 滞销款（N 天内没有转化）；
  - 爆款：提醒补货、推到首页、加入广告投放，并推荐给**其他市场**测试；
  - 滞销款：降价、换主图再测一次，或者下架。
- **新品流**：每个市场的首页有「每日上新」模块，自动显示当天上架的商品。

### 模块 E：按市场的主题和内容

- `StoreTheme` 增加 `market_id`：每个市场一套主题实例，可以从同一个主题复制后修改。
- **预设风格**（第一次创建市场时，可以一键套用）：

| 市场 | 风格建议 |
|---|---|
| 美国 | 简洁、模特图多元化；突出免费退货、满额包邮；黑五、网一、返校季、7 月 4 日活动页 |
| 欧洲 | 克制、留白多；突出含税价、环保材料；GDPR Cookie 弹窗；夏季打折季、黑五 |
| 巴西 / 墨西哥 | 颜色鲜艳、促销感强；**分期付款**和 PIX / OXXO 放在显眼位置；巴西 Black Friday、墨西哥 Hot Sale、Buen Fin |
| 东南亚 | 移动端优先、页面轻；闪购倒计时；突出货到付款和电子钱包；9.9 / 10.10 / 11.11 / 12.12 大促、斋月、开斋节 |

- **活动日历**：每个市场一份节日和大促日历，提前 4–6 周提醒运营准备活动页和选品。
- **尺码**：商品存一份标准尺码，按市场显示 US / EU / UK / BR 尺码，并配换算表。
- 现有的可视化装修器继续使用，只是编辑对象从“店铺主题”变成“某个市场的主题”。

### 模块 F：当地支付和物流

| 市场 | 支付 | 物流 / 税 |
|---|---|---|
| 美国 | 信用卡、Apple Pay、PayPal、Afterpay / Klarna（先买后付） | 中国直发或美国海外仓；按品类计算关税 |
| 欧洲 | 信用卡、PayPal、Klarna、iDEAL（荷兰）、Bancontact（比利时）、SEPA | IOSS、含税价 |
| 巴西 | PIX、Boleto、信用卡分期 | Remessa Conforme、CPF 税号必填 |
| 墨西哥 | 信用卡、OXXO、分期付款（MSI） | — |
| 东南亚 | 货到付款、GCash（菲律宾）、DANA / OVO（印尼）、TrueMoney（泰国）、GrabPay | 本地物流商；货到付款的拒收风险控制 |

- 这些支付大多可以通过 **Stripe**（PIX、OXXO、Boleto、Klarna、iDEAL 等）和 **Airwallex** 接入，项目里已经接了这两家，主要工作是按市场开启和显示。
- 结账页按市场显示必填字段：巴西 CPF、墨西哥邮编格式、印尼省市区三级地址。

### 模块 G：B 端（批发 / 分销）

在现有 `app/B2B` 的基础上扩展：
1. **按市场的批发价**：价格表增加 `market_id` 和币种；阶梯价、起订量、整箱倍数按市场设置。
2. **批发门户**：`/us/wholesale`，企业客户登录后看到批发价、起订量、可以快速批量下单（输入 SKU 和数量）、在线申请报价。
3. **分销 / 代发 API**：给下游卖家开放商品目录和库存接口（CSV 或 JSON 数据流），让他们一键把商品同步到自己的店铺，下单后由我们发货。现有开放平台的 OAuth 和 API Token 可以直接用。
4. **和获客雷达打通**：获客雷达找到墨西哥的批发商 → 转为企业客户 → 自动发送**墨西哥市场的批发目录**（PDF 或在线链接，比索价格）。
5. **供应商端**（后期）：工厂和供应商登录后上传新款、确认采购单、更新库存。这就是 SHEIN 的供应商系统，是做“小批量、快速补货”的基础。

### 模块 H：按市场的数据分析
- 看板顶部可以切换市场：GMV、订单数、客单价、转化率、退货率、毛利（用订单保存的汇率和成本计算）。
- 品类 × 市场的热力图：同一个品类在不同国家的表现。
- 站内搜索词报表（按市场）：**搜了但没有结果的词**，直接推送到选品雷达。

**为什么按这个顺序**：没有“市场”这一层，后面的选品、定价、主题都无处挂。采集和上架排在选品前面，是因为它能马上提高运营效率。测款数据又是选品雷达最好的数据来源，所以先把测款做出来。

**首批市场建议**：美国（客单价高、支付简单）→ 墨西哥和巴西（SHEIN 增长最快的地区，但支付和税更复杂）→ 欧洲（合规要求最多：GDPR、GPSR、VAT）→ 东南亚（客单价低，货到付款多，适合做轻小件）。

## 7. 风险和注意事项

1. **抓取合规**：只采集公开数据或用官方 API；遇到反爬保护不去绕过；尊重 robots.txt；图片版权要提醒运营。浏览器插件只读取运营当前打开的页面。
2. **侵权**：品牌词、知名 IP 图案检测；上架前必须有人工审核。
3. **各国法规**：美国 CPSIA（儿童用品）、加州 Prop 65；欧盟 GPSR（2024 年 12 月起，要求有欧盟境内的责任人）、GDPR；巴西 LGPD。关税政策变化快，所以关税做成可配置的规则。
4. **SEO**：多个市场的页面内容相近，必须正确设置 `hreflang` 和 canonical，否则 Google 会判定为重复内容。
5. **图片版权和成本**：不提供“去除他人水印”的功能；每张图记录来源和授权状态，主力商品逐步换成自拍图。AI 生成图片按张收费，要设置每个店铺每月的额度，并显示每件商品的处理成本。AI 生成的模特图不能误导顾客（颜色、尺寸、质感要和实物一致），否则会推高退货率。
6. **性能**：市场 × 商品 × 价格的数据量会成倍增长。店铺前台的商品列表要按市场缓存（Redis），定价结果要预先计算并保存，不能在打开页面时实时计算。
7. **SaaS 还是自营**：Lumée 本来是多商家的 SaaS。建议把「市场」「采集」「内容工坊」「定价」做成**平台功能**，所有商家都能用；自己的旗舰店作为第一个用户，用来验证效果。选品雷达的数据源要付费，可以作为高级套餐的功能。
