# 各国店铺装修：自动装修与 AI 装修规划

> 2026-11-22。接在 [MARKETS-PLAN.md](MARKETS-PLAN.md)（六个阶段已完成）之后。
> 目标：每个国家的访客看到**为当地设计的店铺**，而不是同一个首页换了语言和币种；运营不用一个国家一个国家手工装修，系统能**自动生成**，也能用一句话让 **AI 装修**，人只负责审核和微调。

---

## 1. 现状

| 能力 | 现在的情况 | 问题 |
|---|---|---|
| 主题 | 两套：Aurora（玫瑰金、衬线体）和 Fresh（绿白，继承 Aurora） | 风格少，都偏“精品店”，没有 SHEIN 式的促销、高密度风格 |
| 装修范围 | 只有**首页**可以加区块（10 种），商品页、分类页、购物车是固定模板 | 商品页、分类页、活动页没法按国家调整 |
| 区块类型 | 首屏大图、精选商品、分类列表、图文、富文本、卖点、评价、FAQ、视频、订阅 | 缺少轮播、倒计时、优惠券条、圆形分类入口、标签页商品、当地支付标识等电商常用区块 |
| 按市场装修 | 市场只能覆盖 10 个字段（公告、购买保障、页脚标语、主色和点缀色、首屏四段文字） | 不能换区块顺序、换商品、换图片、换字体，更不能换整套风格 |
| 编辑器 | 区块拖拽排序、电脑和手机预览、撤销和重做、草稿和发布 | 没有市场切换，看不到“巴西站长什么样” |
| 已有可复用的能力 | 市场预设（美国、欧洲、拉美、东南亚）、活动日历（ShoppingCalendar）、商品 × 市场的销售数据、测款结论、品牌规范（BrandKit）、图片工作室、Claude 接口（`LeadAi::json`）、A/B 测试（Experiments）、主题配置校验（`ThemeService::sanitize`） | 这些数据和能力还没有用到装修上 |

**结论**：缺的是一层“市场装修”数据结构，以及能填充它的生成器。生成器分两种：一种按规则自动生成，另一种由 AI 生成。

## 2. 核心设计

### 2.1 三层叠加：主题 → 风格包 → 市场

```
主题（Aurora / Fresh / 新主题）      模板和区块的代码（Blade）
   └─ 风格包（Style Kit）            一组设计参数：颜色、字体、圆角、密度、按钮、卡片、图片比例
        └─ 店铺装修（主站）           区块列表和设置（现在的 StoreTheme.draft / published）
             └─ 市场装修（每个市场）   在主站基础上改了什么（补丁），或者整套自己的区块
```

- **风格包**把“看起来像哪里的网站”从模板里分离出来。同一套模板，换风格包就能从“欧洲极简”变成“拉美促销”。风格包是数据，不是代码，所以规则和 AI 都能选择、生成。
- **市场装修**有两种模式，每个页面模板单独选择：
  - **跟随主站 + 覆盖**：设置按字段覆盖（编辑器里显示“已为本市场修改 · 恢复”），区块跟随主站。适合欧洲各国这种差别小的市场。
  - **独立装修**：这个市场有自己的区块列表。适合巴西、东南亚这种风格完全不同的市场。
- 现有 `markets.settings.theme` 的 10 个字段迁移成第一种模式下的覆盖项，前台效果不变。

### 2.2 数据结构

```
store_theme_markets
  id, store_id, store_theme_id, market_id
  mode_by_template  JSON   {"home":"own","product":"inherit",...}
  draft / published JSON   {"style":{...}, "settings_patch":{...}, "templates":{"home":{"sections":[...]}}}
  source            manual | auto | ai          （最近一次由谁生成）
  published_at

theme_versions                                   （版本记录：每次发布、AI 生成都留一个版本，可以回滚）
  id, store_id, store_theme_id, market_id NULL, config JSON, source, note, created_by, created_at

theme_schedules                                  （定时切换：活动开始时自动换上活动版本，结束后自动恢复）
  id, store_id, market_id NULL, theme_version_id, starts_at, ends_at, status
```

- 所有写入都经过 `ThemeService::sanitize`：不管人改的、规则生成的还是 AI 生成的，只能出现模板里有的区块和字段，图片只能是店铺媒体库里的。**AI 只产出配置数据，不产出 HTML 和 CSS**，所以不会有 XSS 风险，样式也不会乱。
- 前台渲染：`ThemeContext` 先找当前市场的已发布装修，再回落到主站；按“店铺 + 市场 + 版本号”缓存。

### 2.3 页面模板扩展（参考 Shopify 2.0 的 JSON 模板）

除首页外，以下页面也改成“区块列表”：

| 模板 | 可加的区块 |
|---|---|
| 商品页 | 主信息（固定）、尺码表、当地卖点、搭配推荐、同类热卖、评价墙、物流时效、FAQ、图文 |
| 分类页 | 顶部横幅、子分类入口、筛选栏样式、促销条、商品网格（列数、卡片样式） |
| 活动页（新） | 任意区块组合，可以设置网址，例如 `/pt-br/pages/dia-das-maes`，用于节日大促 |
| 购物车 | 免邮进度条、凑单推荐、当地支付标识 |

### 2.4 新区块（按跨境快时尚常用的版式）

| 区块 | 作用 | 主要用在 |
|---|---|---|
| 轮播横幅 | 多张横幅自动轮播，手机端和电脑端分别上传图片 | 所有市场 |
| 圆形分类入口 | 一排圆形图标，可以横向滑动 | 东南亚、拉美（手机端） |
| 限时抢购 | 倒计时 + 商品横滑，时间到了自动隐藏 | 东南亚、拉美 |
| 优惠券条 | 展示可领取的折扣码，点击复制 | 拉美、东南亚 |
| 标签页商品 | “新品 / 热卖 / 低价”切换 | 所有市场 |
| 本市场热卖 | 按这个市场近 14 天的销量自动排列，不用手动维护 | 所有市场 |
| 跑马灯 | 一行滚动的文字（免邮、退货、分期） | 美国、拉美 |
| 当地信任条 | 当地支付方式图标、关税说明、退货政策；内容按市场自动生成 | 欧洲、拉美 |
| 分期提示 | “12x sem juros”“MSI 3/6/12 meses”，金额按价格自动计算 | 巴西、墨西哥 |
| 买家秀墙 | 带图评价瀑布流 | 美国、欧洲 |
| 场景图热点 | 一张场景图，标出可购买的商品 | 欧洲、美国 |

每个区块都有**手机端单独设置**（例如图片、列数、是否显示），因为东南亚和拉美九成以上的流量来自手机。

### 2.5 各地区风格包（默认值，可以改）

| 风格包 | 视觉 | 首页区块顺序 | 说明 |
|---|---|---|---|
| 美国 · 大图简洁 | 白底，黑字，一个品牌色；粗体无衬线；大图，留白多 | 首屏大图 → 跑马灯 → 本市场热卖 → 分类大图 → 买家秀 → 订阅 | 强调品牌感、退货政策、先买后付 |
| 欧洲 · 极简可信 | 低饱和颜色，细字体，小圆角 | 首屏 → 新品 → 场景图热点 → 信任条（含税、30 天退货、GPSR） → FAQ | 价格写“含税”，信任条写清楚责任人和退货 |
| 拉美 · 热闹促销 | 高饱和颜色（品牌色 + 黄色或粉色），大号价格，较大圆角 | 轮播 → 优惠券条 → 圆形分类 → 限时抢购 → 分期提示 → 本市场热卖 | 突出分期、免邮门槛、Pix / OXXO |
| 东南亚 · 高密度移动端 | 红色或橙色点缀，紧凑卡片，每行两个商品 | 轮播 → 圆形分类 → 限时抢购（9.9、11.11 等）→ 优惠券条 → 标签页商品 | 首屏就要看到商品，图片压缩到最小 |
| 中东 · 从右到左 | 深色或金色，阿拉伯文字体，**页面从右到左排版** | 首屏 → 斋月或开斋节活动 → 热卖 | 需要先做从右到左的布局支持（见阶段 A） |

不同文字使用不同字体：日文用 Noto Sans JP，泰文用 Noto Sans Thai，阿拉伯文用 Noto Naskh Arabic。风格包里写的是西文字体，系统按语言自动补上对应文字的字体。

## 3. 自动装修（按规则生成，不依赖 AI）

在「在线商店 › 市场装修」中点击「为这个市场生成」，或者新建市场时勾选“自动生成店铺”。生成器读取以下数据：

```
市场（国家、语言、币种、预设） ─┐
活动日历（接下来 30 天的节日）   ─┤
本市场销量、测款潜力款           ─┤
分类和商品（按这个市场的上架范围）─┼─→ 生成器 ─→ 草稿（不会自动发布）
当地支付方式、关税模式、免邮门槛 ─┤        └→ 检查报告
品牌规范（品牌色、语气、禁用词） ─┘
```

1. **选风格包**：按市场预设（us / eu / latam / sea / me）。如果主站有品牌色，就把风格包的主色换成品牌色，其他颜色按对比度重新计算（已有 `Color::mix` 和 `Color::luminance`）。
2. **排区块**：按风格包的顺序，跳过没有数据的区块（例如没有折扣码就不放优惠券条，商品少于 4 个就不放标签页商品）。
3. **填内容**：
   - 商品：本市场热卖 → 测款潜力款 → 新品，只选这个市场上架的商品。
   - 分类：本市场销量最高的 4 到 8 个分类。
   - 文字：从预设的当地语言文案库取（现在已有公告和购买保障，要扩充到首屏、按钮、区块标题）；没有的用已有的翻译功能翻译。
   - 数字一律从配置读取：免邮门槛来自运费设置，分期期数来自支付设置，关税说明来自关税模式。**文案里不写死数字**，避免出现“满 $99 包邮”但实际门槛是 $49 的情况。
   - 图片：首屏优先用品牌规范里的横幅图，其次用热卖商品的场景图；都没有的话，用图片工作室合成横幅（商品抠图 + 品牌色背景 + 文字），这一步不需要外部服务。
4. **活动自动排期**：活动日历里接下来的节日，提前（日历里的准备天数）生成活动版本，并加入定时切换：开始时自动换上，结束时自动恢复。运营在首页的“待办”里看到“巴西母亲节首页已生成，待审核”。
5. **装修检查**（每次生成和发布前都会运行）：
   - 文案里的数字和店铺配置是否一致（免邮门槛、退货天数、分期）。
   - 是否有没翻译的文字（例如巴西站出现英文）。
   - 颜色对比度是否达到 WCAG AA。
   - 手机端首屏是否能看到商品，首屏图片是否超过 300KB。
   - 是否缺少当地必需的内容：欧洲的含税说明和 GPSR 信息，巴西的 CPF 提示。
   - 商品链接是否指向这个市场没有上架的商品。

## 4. AI 装修

### 4.1 一句话生成

在编辑器里输入：“给巴西站做母亲节首页，温暖一点，主推项链和刻字款，预算 R$ 200 以内的放前面。”

```
需求 + 市场信息 + 品牌规范 + 商品和分类摘要 + 可用区块和字段（主题 schema）+ 风格包
        │
        ▼
Claude（LeadAi::json，按 JSON Schema 输出）
        │  输出：风格包调整、区块列表和每个字段的值、选用的商品和分类 ID、每个区块的设计理由
        ▼
ThemeService::sanitize（只保留合法的区块、字段、商品和图片）→ 装修检查 → 草稿 + 版本记录
```

- **AI 输出配置，不输出代码**。区块和字段都来自 schema，所以 AI 生成的页面可以在编辑器里继续手动修改，和手工装修的页面没有区别。
- **当地化写作，不是翻译**：提示词里带上当地的购物习惯（巴西用“frete grátis”“12x sem juros”，母亲节在 5 月第二个周日；墨西哥母亲节固定在 5 月 10 日），以及品牌规范里的语气和禁用词。
- **商品由数据决定**：AI 只能从系统给出的候选商品里选（本市场热卖、潜力款、符合价格条件的商品），不会编造商品。

### 4.2 编辑器里的 AI 助手

编辑器右侧有一个对话面板，可以连续修改：

- “首屏太素了，换成促销风格” → AI 给出修改方案，预览里显示修改前后的对比，点「应用」才写入草稿。
- “把这个首页做一个墨西哥版本” → 复制成墨西哥站的独立装修，文案改写成墨西哥西班牙语，支付方式换成 OXXO 和分期。
- “检查一下这个页面” → 运行装修检查，再加上 AI 的设计建议（例如信息太多、行动按钮不明显、和品牌规范不一致）。

**AI 不会直接发布**。所有修改先进入草稿并留下版本记录，可以一键回滚。

### 4.3 AI 图片（需要接入图片生成服务）

- 横幅和活动主视觉：按品牌色和活动主题生成背景，商品图用实拍抠图合成，**不让 AI 画商品本身**，避免和实物不一致。
- 和测款阶段没做完的“AI 场景图、模特图”使用同一个图片服务接口，做成可替换的服务商（`ImageGenerator` 接口），每个店铺可以设置每月的额度。
- 没有配置图片服务时，退回到图片工作室的合成横幅，功能照样可用。

### 4.4 用数据验证效果

- 同一个市场的两个首页版本可以做 A/B 测试（复用现有的 Experiments：按访客分组、z 检验），比较加购率和转化率。
- 测试有了明确结果后，提示“版本 B 的转化率高 18%，是否全部切换”，由人决定。
- 后期：AI 每周根据各市场的数据给出装修建议（例如“东南亚站首屏跳出率高，建议把限时抢购移到第二屏以内”）。

## 5. 先把没做完的功能补齐（阶段 0）

前六个阶段留下的缺口，分成“只需要写代码”和“需要外部账号”两类：

| 缺口 | 来源 | 做法 | 需要外部账号吗 |
|---|---|---|---|
| 商品列表按价格排序用的是店铺价格，不是市场价格 | 阶段一 | 按市场价格排序（预先算好市场价并保存） | 不需要 |
| README 写着“主题文案不能按市场设置”，但阶段五已经做了 | 文档 | 更新文档 | 不需要 |
| 货到付款 | 阶段五 | 作为一种按市场开启的线下付款方式，订单状态为“待收款”，收到货款后标记已付款；可以设置手续费和金额上限 | 不需要 |
| 墨西哥分期（MSI） | 阶段五 | 用 Stripe 的卡分期（`installments`），结账显示 3、6、12 期 | 需要墨西哥的 Stripe 账户 |
| 巴西分期（parcelamento） | 阶段五 | Stripe 巴西账户的分期，或者接入 Mercado Pago | 需要巴西的 Stripe 账户或 Mercado Pago 账户 |
| 分销商不能通过接口下单 | 阶段六 | 批发目录增加下单接口（使用目录的私密令牌、按价格表定价、检查起订量），生成待确认的批发订单 | 不需要 |
| 礼品卡不能作为商品出售 | 早期 | 新增“礼品卡”商品类型，付款后自动发卡并发邮件 | 不需要 |
| AI 场景图、模特图 | 阶段三 | 和 4.3 一起做，使用同一个图片服务接口 | 需要图片生成服务的密钥 |
| TikTok、Keepa 等选品数据源 | 阶段四 | 在选品雷达里增加数据源接口，密钥在设置里填写 | 需要对应服务的付费账号 |
| 后台菜单整理 | 本次 | 已完成 | — |

**只需要写代码的部分可以直接做完**；需要外部账号的部分，先把接口和设置页做好，填入密钥后就能使用，没有密钥时页面上会说明需要什么。

**阶段 0 完成情况（2026-11-23）**：
- 按市场价格排序、货到付款、分销商下单接口、分期付款（Stripe）、AI 场景图（OpenAI，可替换）都已完成，并有测试覆盖。
- 礼品卡其实早就可以作为商品出售，只是文档没有更新；这次补上了“送给别人”（收件人邮箱、名字、留言）。
- TikTok、Keepa：改为导入它们导出的 CSV（TikTok 没有公开的趋势接口，Keepa 的接口需要付费账号，无法在本地验证），数据计入选品评分。
- 顺带修复：用 Stripe 付款时，进口关税没有算进明细行；礼品卡抵扣一部分时，Stripe 会按全额收款。现在明细合计和应付金额不一致时，改为按应付总额收一行。
- 需要外部账号才能真正使用的：分期付款需要墨西哥 / 巴西的 Stripe 账户；AI 场景图需要图片生成服务的 API Key。

- 每周建议：每周一 06:00（`lumee:design-insights`）分析上周访问 50 次以上的站点。先按规则找问题（手机跳出高、首页跳出高、加购率低、手机转化不到电脑一半、转化率下降），再请 Claude 用店主的语言给 2–4 条具体的改版建议（占用 AI 装修额度，没有密钥时只给规则发现）。也可以在看板里点「现在分析」。

**为什么按这个顺序**：没有“市场装修”这一层，自动生成和 AI 生成的结果就无处保存，所以 A 必须先做。B 决定了能生成多丰富的页面。C 先于 D，是因为规则生成器同时也是 AI 的兜底方案（没有配置 AI 密钥或 AI 出错时仍然可用），而且装修检查能同时检查规则和 AI 生成的结果。

## 7. 风险和注意事项

1. **编辑器复杂度**：多了市场这一维，编辑器很容易变得难用。规则是：默认只显示主站，切换到某个市场后，只有被覆盖的字段才有标记，“恢复默认”随时可以点。
2. **维护成本**：每个市场独立装修后，改一次主站不会自动同步到所有市场。所以优先用“跟随 + 覆盖”，只有确实需要时才独立装修；主站修改了被市场覆盖的字段时，给出提示。
3. **AI 成本和失控**：AI 生成要设置每个店铺每月的次数上限；所有 AI 结果先进入草稿，发布必须由人确认；生成记录保存在版本记录里，可以追溯。
4. **文案准确性**：价格、门槛、退货天数、分期期数一律从配置读取，装修检查会拦截不一致的文案。广告法和当地消费者保护法（例如欧盟的划线价规则：划线价必须是 30 天内最低价）也要列入检查项。
5. **性能**：每个市场一套配置后，缓存键要包含市场和版本号；手机端的图片按尺寸裁剪，首屏图片预加载。
6. **从右到左排版**：中东市场要求整站布局镜像，现有模板里的左右方向样式要改成逻辑方向（`margin-inline-start` 等），工作量比较大，所以放在阶段 A 统一处理。
